# Colo Design — 화면 구성 재설계 브리프

## 제품
비개발자(기획자·디자이너·운영자)가 개발자의 레포에 연결해 **채팅으로 화면을 만들고 고치는** 데스크톱 앱 (Electron+React). git/터미널/Claude Code를 모르는 사람이 대상. 입력은 말과 그림뿐. git 용어는 "저장/개발자에게 넘기기/반영됨" 세 단어로 번역된다. 한 사람·한 기계·하나의 Claude 구독.

## 사이클 (제품의 유일한 정신 모형)
말하기 → 화면 대화(Claude 세션) → 미리보기(레포의 실제 앱) → 핀으로 수정 지시 → 저장(브랜치에 커밋·푸시) → 개발자에게 넘기기(PR) → 반영됨(병합) → 새 사이클. 상태 칩: 변경 없음/저장 안 함/저장됨/개발자 검토 중/변경 요청/반영됨/개발자가 반려함/치워둔 작업.

## 현재 화면 구성 (3열)
- 왼쪽 레일: 브랜드 + 프로젝트 트리(프로젝트 노드 → 대화 leaf, 상태 점·메타) + 검색 없음(⌘K 팔레트만) + 푸터(새 프로젝트·설정). 접힌 모드 있음(모노그램 타일).
- 가운데: 대화 열 — 사용자 ❯ 로그 카드, 답변 산문, 접힌 도구 합산 줄, 화면 칩, 허가 카드, 컴포저(모델/빠르게/확인 방식/컨텍스트 링 칩, 첨부, 핀 트레이, 큐, 제안 칩, 보내기/중지).
- 오른쪽: 미리보기 — 사이클 바(상태 칩+더 보기+저장+넘기기), 도구줄(화면 목록·상태 칩·핀 모드·폭 토글·새 창), 브라우저 크롬(뒤/앞/새로고침/주소), 스테이지(실제 앱 또는 오류/빈 상태).
- 모달/드로어: 저장 검토(diff), 넘기기, 저장 기록, 개발자 코멘트, 설정, 온보딩 게이트, 레포 선택, 단축키 시트, ⌘K 팔레트.

## 최근에 바뀐 것들 (레이아웃에 영향)
- 단일 인스턴스 앱; 데몬이 포트를 다시 잡아 origin 안정.
- 멀티프로젝트: 한 번에 하나 활성이지만 떠난 프로젝트의 미리보기는 웜 상태(최근 2개), 다른 프로젝트의 Claude 작업은 계속 돌고 사이드바 표식이 알림.
- 실행 중 보내기: 다음 턴 큐 / 끊고 보내기(⌥Enter). 보낸 말은 데몬이 붙듦(앱 죽어도 남음).
- 핀: ⌥+클릭으로 미리보기에 찍고 컴포저 트레이에 행. 보낸 코멘트는 대화록 카드 + PR 본문 '수정 요청' 목록.
- 잠깐 치워두기: 저장 안 한 작업 통째 보관(자리 1개).
- 알림: 완료/확인 요청/저장 실패 → OS 알림+dock 배지, 클릭 시 그 대화로 전환. 확인 요청·중단은 언제나 옴.
- 진행 시계는 데몬 소유(창 새로고침·두 번째 창에서도 이어 셈).
- 되돌리기 3종: 요청 이전으로 / 다시 요청 / 저장 기록에서.
- 계획 칩(Plan 모드): 첫 답이 '만들 것' 카드 → 승인/거절.
- 대화보내기(markdown), 스레드 삭제, 자동명명.

## 이미 검토된 개선 방향 (docs/mockup-improvement-review.md)
- "정보가 hover tooltip 뒤에 있다"가 7개 표면의 체계적 결함 → 행동 옆 설명은 인라인, 상태 표지는 사건 시에만.
- '기다림'의 언어 통일(동사+경과초), 파괴 확인에 '남는 것' 명시.
- 사이클 진행 레일은 의도적으로 삭제된 것(delivery.ts) — 스테퍼 부활 금지, 대신 다음 단계를 말하는 방식 필요.
- 모달 고정 푸터, 허가 카드 결과 표기, 빈 스테이지 empty state 등 20건 채택됨.

## 당신의 과제
"프로젝트가 많이 바뀌었으니 화면 구성을 다시 생각해도 된다"는 전제에서, **이 앱의 화면 구성(정보 아키텍처+레이아웃) 대안을 하나 제안**하라.

요구 형식:
1. **한 줄 주장** — 이 구성이 말하는 것 (예: "대화가 주인공이다"를 버리고 "…"를 주인공으로).
2. **ASCII 레이아웃** — 창의 구획과 각 구획의 내용.
3. **현재 3열과의 차이** — 무엇이 어디로 갔는지, 무엇이 사라지고 생겼는지.
4. **근거** — 위 '최근에 바뀐 것들' 중 이 구성이 풀어내는 것. 기획자(비개발자) 관점에서.
5. **대가·리스크** — 이 구성이 잃는 것, 깨지는 불변식.
6. **첫 화면** — 앱을 처음/다시 열었을 때 사용자가 보는 것.

제약: 비개발자 대상, git 용어 금지, 따뜻한 종이 톤 유지, 실제 구현 가능성(React/Electron, 기존 컴포넌트 재사용 선호). 과감해도 되지만 "왜 지금 구조가 틀렸는지"를 먼저 답할 것. 필요하면 repo의 packages/web/src/components 와 mockups/ 를 읽어라. 결과는 마크다운으로 반환.
