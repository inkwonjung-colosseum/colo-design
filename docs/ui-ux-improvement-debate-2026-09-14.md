## 2. findings 상세 (1라운드 원형 + 2라운드 보강)

### F-A1 — 상태 칩은 마지막 클릭의 기억이다 (영향 5 / 비용 2)

- **증거**: GitHub을 다시 읽는 유일한 호출 `api.handoffStatus()`의 호출자는 `상태 확인` 버튼 하나(ScreenPanel.tsx의 `checkHandoffState` — 자동 호출 경로 없음). 칩이 읽는 `handoff.state`(delivery.ts)는 daemon이 저장한 사이클의 복원·갱신 시점(넘기기/상태 확인)에만 움직인다. 저장도 기존 넘김을 재조회 없이 그대로 넘긴다(daemon repo.ts `setCycle`). 개발자 코멘트 배지의 원천도 같은 경로.
- **2라운드 프레임 교정(B)**: README 스스로 수동 확인을 문서화한다("진행은 `상태 확인` 버튼으로 본다"). 위반이 아니라 README의 "칩 하나가 지금 어디쯤인지 말한다"와의 **자기모순이자 UX 공백**.
- **수정 전제(C·B)**: (1) `checkHandoffState`는 `setDevPanelOpen(true)`까지 겸한다 — 조용한 자동 갱신에 그대로 쓰면 프로젝트 열 때마다 코멘트 패널이 튄다. 갱신과 패널 오픈 분리가 전제. (2) 데몬 `refreshHandoff`는 병합 시 fetch/checkout/reset + 체크포인트 삭제를 수행한다(주석 스스로 "not a passive status read"). 이 부작용은 README의 "화면 작업 시작 때 받아 온다"와 방향이 맞으므로 허용 가능하나 판단은 필요.
- **현상의 실례(B)**: 반영 전 세션 시작 최신화가 클론에 병합을 끌어와도 칩은 `개발자 검토 중` — 클론과 칩이 어긋나는 창이 실재.
- **최소 수정**: 열린 넘김이 있으면 프로젝트 활성화(또는 소켓 재연결) 시 조용한 읽기(패널 오픈 제외) 1회. 더 작게는 칩 title에 "마지막 확인 HH:MM".

### F-C1 — 한글 확정 Enter가 곧 실행 (영향 4 / 비용 1)

- **증거**: ⌘K 팔레트(Palette.tsx onKeyDown — Enter→첫 결과 실행, Escape→닫기, 조합 중에도 매입력 첫 행 강조)와 레포 피커(RepoPicker.tsx, Enter→선택 흐름 개시)에 `isComposing`/keyCode 229 가드 없음. 2라운드에서 **이름 바꾸기 입력 3곳 추가 발견(B)**: 스레드(ChatColumn.tsx), 프로젝트·레포의 이름 바꾸기(Sidebar.tsx 2곳) — 조합 확정 Enter가 이름을 조기 확정한다. (의장 실측: ChatColumn 이름 바꾸기 Enter 처리에 가드 없음 확인.)
- **대조군**: 같은 가드가 코드베이스에 이미 4곳(Composer 2곳, PinTray, components.tsx) 주석과 함께 존재 — 결함이 아니라 누락.
- **심각도 논쟁(기록)**: A "높음 — 한글 검색은 확정 Enter마다 튕겨 나가므로 검색 기능 자체를 못 쓴다(빈도 100%)" vs B "중간~높음 — 실행 결과가 이동·검사 시작에 그친다(유한)". 의장: 한국어 UI 1급 표면의 상시 결함이며 수정이 한 줄×5곳 — top-5 유지.
- **최소 수정**: 다섯 `onKeyDown` 첫 줄에 `if (event.nativeEvent.isComposing || event.keyCode === 229) return;` (Composer의 기존 가드와 동일).

### F-C2 — 보내기 진행 중 잠금 없음 (영향 4 / 비용 1)

- **증거**: `submit()`은 빈 값 검사만; 입력창 비움은 데몬 수락 뒤(PLAN D35 — 수락 전까지 문장을 쥐는 것이 설계). 보내기 버튼의 disabled 조건에 "전송 중"이 없고, 하위 체인(useSessions.submit → api.send)에도 재진입 가드 없음.
- **2라운드 격상(B)**: 활성 세션이 없을 때 `targetSession`은 `!id → startSession`(useSessions.ts — 주석 스스로 "would open a second, nameless thread" 경고). 첫 Enter의 세션 생성이 끝나기 전 두 번째 Enter는 다시 `!id`로 들어가 **두 번째 스레드**를 만든다. 첫 전송은 기획서(PDF) 첨부로 가장 느리고, D35가 입력창을 채워 두므로 "안 갔나?" 재입력의 창이 설계상 열려 있다. "잠금은 D35의 빠진 반쪽". (의장 실측: useSessions.ts 해당 경로 확인.)
- **덧붙임(A·B)**: 두 번째 Enter는 핀·첨부까지 함께 재전송. F-B3의 `다시 보내기`도 같은 submit 경로를 지나므로 잠금이 들어가면 함께 보호.
- **최소 수정**: `submit` 진입 동기적으로 `sending=true`(ref), `.then`/`.catch`에서 해제; sending 중 Enter 경로·보내기 버튼·FailedTurn의 onRetry 무시. 실패 시 보존(D35)은 그대로.

### F-A3 — 답변 본문이 개발자 어휘로 쓰인다 (영향 3 / 비용 1)

- **증거**: 실제 Claude 출력(ui-planner-e2e 스크린샷; 테스트에 스텁 없음 — B 확인)의 `만든 화면` 목록이 파일 경로·콜백·prop 이름으로 적힘. 원천은 모든 세션에 예외 없이 주입되는 공통 규칙 한 줄 "화면의 이름과 **경로**를 답변 끝에 남긴다"(daemon common-instructions.ts) — 이 코드베이스에서 "경로"는 파일 경로를 뜻한다.
- **내부 모순(전원 확인)**: 기계 요약·저장 메모·넘기기 프롬프트는 셋 다 "파일 이름 없이"(repo.ts 3곳)를 못 박고, README도 "파일 경로 없이, 컴포넌트·prop 이름 없이, 화면과 기획서는 제목으로"라고 배운다고 쓴다. 기획자가 가장 많이 읽는 대화 답변에만 그 규칙이 없다.
- **안전성(B)**: "답변 끝" 경로 형식을 소비하는 파서가 웹·데몬·프로토콜에 없음(grep 0건) — 교체가 코드를 깨지 않는다. 단 준수는 확률적(B).
- **최소 수정**: 지침 문장을 "화면 제목과 화면 주소를 답변 끝에 남긴다. 파일 경로·컴포넌트·prop 이름은 답변에 쓰지 않는다."로 — 상수 한 줄(앱 릴리스 소유 규칙이므로 변경 기록).

### F-A2′ — 입력창 어휘 유출, 축소 범위 (영향 3 / 비용 1)

- **1라운드(A)**: 자리표시자 `…@files 태그, /commands 를 사용하세요`(스크린샷 4장 전부) + 영어 칩 라벨(Low…Max, Bypass) + 링 툴팁 `세션 비용 $0.29`·토큰 수.
- **2라운드 수렴(전원)**: 칩 라벨 영어는 **문서화된 결정**(chat-options.ts 머리주석 — "CLI 고유 이름이 검색·이슈·터미널 대조에서 살아남는다")이므로 전면 한국어화는 결함 수정이 아니라 결정 변경. F-A2는 둘로 좁힌다:
  1. **`세션 비용 $`·토큰 두 줄 삭제**(ContextRing 툴팁) — 같은 코드베이스가 대화록에서는 "Cost stays invisible."을 규칙으로 적어 뒀고(의장 실측 components.tsx:1153), "한 사람·한 구독" 제품 약속과 정반대 인상. 다만 hover/focus 시에만 보이는 2차 정보(C)라는 감점은 기록.
  2. **자리표시자 다듬기** — @// 는 입력 문법을 가르치는 기능(주석의 D83 결정)이므로 삭제가 아니라 자연스러운 한국어로(예: `기획서를 첨부하고 싶은 화면을 말해 보세요 (@로 파일, /로 명령)`). **D83 번복으로 기록해야 한다.**
- **F-B2 흡수 요건(B)**: 기본값 칩 라벨은 컨텍롤 이름을 포함해야 한다(`모델 자동`·`생각 자동`) — 그냥 `자동`으로 바꾸면 `자동 ▾ 자동 ▾`이 남는다. 또 README가 "`계획 먼저` 칩"이라 부르는 동작이 화면에서는 글자 없는 ⚡ 아이콘(aria-label만) — 글자를 붙이거나 README를 고치되 둘 중 하나는 움직여야 한다.
- **열린 선택(기록)**: A의 절충안 — 모델·노력 이름은 CLI 원문 유지하되 `확인 방식` 칩만 한국어화(기본값이 `Bypass`=확인 없이 진행이라 안전 정보). 1/3 지지, 채택 시 결정 변경 절차로 처리(C).

### F-B1 — 핵심 동작 라벨의 글자 중간 절단 (영향 3 / 비용 1)

- **증거**: 960px 스크린샷에서 `개발자에게 넘기ː` 마지막 글자가 세로로 반쯤 절단(말줄임 없음). 원인: `@media (max-width:1100px) .screenpanel__action[title]{overflow:hidden;text-overflow:ellipsis;max-width:88px}`(styles.css) — 버튼이 inline-flex이고 라벨이 아이콘 옆 맨 텍스트 노드(익명 flex 아이템)라 `text-overflow`가 적용되지 않고 하드 클립만 남는다. 88px는 가용 폭과 무관한 고정값. 창 minWidth 없음(desktop main.ts) — 13" 반분할이 이 구간.
- **2라운드 심화(A·C)**: 선택자가 `[title]`이라 규칙은 **잠긴 버튼에만** 걸린다(title은 잠김 이유가 있을 때만 존재). 즉 절단은 잠긴 상태 — **기본 부팅 상태 `변경 없음` 포함** — 에서 발화하고, 정작 눌러야 할 `저장됨`(열림) 상태에서는 상한 자체가 없어 바가 밀린다. 같은 버튼이 상태마다 다르게 부서진다. README가 "잠긴 버튼은 이유가 뜬다"고 약속한 바로 그 요소가 잘린다.
- **심각도 조정(기록)**: B 스스로 높음→중간 하향(≤1100px 창 대역 한정). A·C는 top-5 3위 유지. 의장: 결정적 CSS 수정이라 순위와 무관하게 같은 PR에 태우는 것으로 정리(B 권고 채택).
- **최소 수정**: 라벨을 `<span>`으로 감싸 그 span에 ellipsis 이전, 미디어쿼리 개정(잠김 여부가 아니라 폭에만 반응하게). 1100 이하 아이콘 숨김으로 폭 확보 병행 가능.

### F-B3 — 실패 카드의 1차 버튼 남발 + 잘못된 문장 재전송 (영향 3 / 비용 2)

- **증거**: FailedTurn은 항상 `className="primary"`(components.tsx)이고, Transcript가 모든 실패 카드에 같은 `retryText={lastUserText(blocks)}`를 심는다 — `lastUserText`는 전체 대화에서 **마지막** 사용자 문장을 돌려주므로 오래된 카드의 `다시 보내기`를 누르면 최신 문장이 나간다(시각적 약속 위반 — A가 "위계 문제가 아니라 동작 결함"으로 격상). 한 화면에 ink 1차 버튼 3개+가 겹칠 수 있다(스크린샷 실측).
- **조정(C)**: styles.css의 "강조는 하나에만" 주석은 상단 바 동작 셋에 한정된 서술이지 전역 규칙 선언은 아니다 — 다만 항상-primary + 잘못된 재전송의 조합은 인용 없이도 성립.
- **최소 수정**: `retryText`는 마지막 실패 블록에만 전달(한 줄), 나머지 카드는 `자세히`만; 카드 버튼은 회색 급으로 강등. F-C2 잠금이 들어가면 onRetry도 같이 보호.

### F-C3 — × 닫기의 히트 영역 (영향 2 / 비용 1)
