보내기·큐·데몬 소유 시계**: 앱을 닫았다 열어도 작업이 진행 중이다. 홈이 \"뭐가 돌고 있지\"에 즉시 답한다 — 재진입의 첫 화면이어야 하는 이유.\n- **잠깐 치워두기**: 자리 1개짜리 기능이 메뉴에 묻혀 있으면 잊힌다. 카드로 올라오면 \"아, 치워둔 게 있었지\"가 공짜로 일어난다.\n- **계획 칩·허가 카드**: \"승인/거절을 기다리는\" 상태가 대화 안에만 있으면 다른 일을 하다 놓친다. 인라인 액션 카드가 그 출구다.\n- **웜 미리보기(최근 2개)**: 받은편지함 카드 → 작업 모드 진입 시 웜 미리보기가 즉시 뜬다 — \"떠난 프로젝트도 바로 이어진다\"를 체감으로 바꾼다.\n- **미리보기 접힘**: 사이클의 절반은 볼 화면이 없다. 빈 열 대신 대화가 전폭을 쓰고, 화면이 생기는 순간(첫 스크린 등록·핀 모드·재그리기 완료)에만 패인이 열린다. 리뷰의 \"상태 표지는 사건 시에만\" 원칙과 같은 논리를 레이아웃에 적용한 것이다.\n\n## 5. 대가·리스크\n\n- **새 데이터 조립**: 받은편지함 카드는 세션 상태·큐·허가 대기·넘기기 판정·치워둠을 프로젝트으로 모은다. 소스는 대부분 이미 존재(`sessions`, `delivery`, `repo.shelf`)하지만 카드 한 줄 문장(\"공용 버튼 파일을 고쳐도 될까요?\")은 새 직렬화 — MEDIUM.\n- **미리보기 접힘의 구현 비대칭**: `IframeHost`는 `display:none`으로 충분하나 `NativeHost`(WebContentsView)는 main process가 bounds를 관리 — 접힘은 unmount가 아니라 bounds 0/오프스크린 이동이어야 웜 상태와 게이트가 산다. 데스크톱 브리지 작업 MEDIUM. 게이트·넘기기 캡처는 숨은 드라이버라 무관.\n- **상태 칩 이동**: `delivery` 계산이 `ScreenPanel` 안에 있으므로 헤더가 읽으려면 `PageWorkspace`로 hoist — 구조 변경 MEDIUM. \"동작은 상수다\" 불변식(항상 그려지고 조건으로 잠김)은 헤더에서도 그대로 유지해야 한다. 두 곳에 두는 중복은 금지.\n- **잃는 것 — \"작업 = 화면\" 감각**: 미리보기가 접히면 화면을 안 보고 저장을 누르는 경로가 생긴다. 완화: 저장 검토 모달의 diff가 마지막 확인으로 남고, \"새 화면이 그려졌다\" 사건 시 자동 펼침 또는 헤더 표식.\n- **받은편지함이 제2의 대화가 되는 함정**: 카드는 문이지 방이 아니다 — 카드 안에서 답을 쓰게 하지 않는다(곁대화는 별도 제안 `ideas/side-chat`의 몫).\n- **빈 홈의 데드엔드**: 일이 0건인 받은편지함을 강제로 보여주면 죽은 화면. 규칙: **일이 있을 때만 홈이 되고, 없으면 마지막 대화로 바로
