## 2. 채택 제안 상세 (2라운드 교정 접힘)

### 1위 A-1 — 기획서는 프로젝트가 생기는 순간 화면에서 사라진다 (5/2)

- **빈 곳**: 프로젝트 0개 화면은 제품 전체를 기획서로 말하지만(Shell.tsx:414, 434) 프로젝트가 생기면 hero가 통째로 사라지고(:404), 빈 대화 문구(`components.tsx:958,960`)·시작 칩 3종(`suggestions.ts:7-31`)·세션 열린 뒤 자리표시자(`PageWorkspace.tsx:501`)에 기획서가 한 글자도 없다. 첨부는 글자 없는 `+` 아이콘(`Composer.tsx:1210-1218`). 결정타: 기획서를 빈 대화에 끌어다 놓으면 **아무 일도 안 일어난다** — 드롭 핸들러는 입력창에만 있고(`Composer.tsx:892-896`) 나머지는 전역 거절(`App.tsx:121-129`, 주석 스스로 자백). README 첫 줄의 약속(`:3`)이 실행 지점에서 증발한다.
- **최소판**: ① `+` 버튼에 글자 `기획서` 부여(B) + 빈 대화 첫 칩을 동작 칩 `기획서 첨부하고 시작하기`로(파일 피커 + 문장 초안), ② **드롭존을 컴포저 영역 이상으로 확장** — B 보강: 두 번째 기획서는 빈 대화가 아닌 곳에 떨어지므로 대화 열 전체(`.planner__chat`), ③ 자리표시자에 `기획서` 복귀. dragleave 카운터 필수(C).
- **감동판**: 드래그 시 빈 대화 면적이 받는 피부(포커스 링 문법, styles.css:2138-2146)를 입고 hero 미니어처(320px→860px)가 `width 0.35s var(--drift)`로 읽기 폭을 입음 — **새 토큰 0·새 색 0**(C 실측). 단 1초가 아니라 집 박자(0.35~0.55s)로.
- **짝**: C-5(첨부 칩을 "뿌리 문서"로 — `bubble__file`이 basename만·클릭 불가 `components.tsx:1079-1083`, 실물은 클론 `specs/`에 영속 `session.ts:1046-1050`)를 같은 PR에 — 입구와 뿌리가 같은 객체(A).

### 2위 B1+C-3 — 반영됨·변경 요청이 기획자를 찾아오고, 도착이 사건이 된다 (5/1·감동 3)

- **빈 곳**: 조용한 재판독 트리거는 프로젝트 전환 1회뿐(`ScreenPanel.tsx:433-435`) — 하루 한 프로젝트·주말 건너뛰기엔 트리거가 없다. `DaemonNotice`는 `done|crashed|ask|gate`뿐, 개발자 쪽 사건 없음(`server.ts:148-161`). 나침반 여섯 칸 중 마지막 두 칸만 수동(A의 프레임). 사이드바 배지는 있지만 같은 이유로 움직이지 않는다.
- **최소판(비용 1)**: `readHandoffState(true)`를 visibilitychange/focus에서도 호출(≥5분 스로틀, running 중 스킵).
- **감동판(비용 3)**: 열린 넘김이 있는 워크스페이스마다 10분 폴링(GitHub 읽기 6회/시간 안), 상태 전이 시 `DaemonNotice {kind:"handoff"}` → OS 알림(프로젝트 이름 단위 — A 수정), 클릭 시 그 프로젝트로 전환(sessionId 없는 사건이라 **slug 전환 경로 필요** — B 함정 지적).
- **채택 조건(C)**: `handoffStatus()`는 `refreshHandoff()`다(`server.ts:1941-1942`) — 어제 판정문의 "not a passive status read"(fetch/checkout/reset). 스킵 목록(running·publishing·refreshing)에 이 판정 유지를 명시.
- **C-3의 두 반쪽**: ① **펄스+글리프 분리**: `state === "merged"` 진입에 칩·사이드바 배지 `settlepulse` 1회(tone 감시 X — 도는 동안 pending 덮어쓰기로 재펄스, B 함정). 주석 "the one moment worth celebrating"(`styles.css:4803-4805`)이 색만 지키고 글리프를 놓친 것의 회복. ② 감동판 OS 알림은 B1이 소유(중복 구현 금지). `notifyPlanner`가 `isFocused()`면 조기 반환(`main.ts:559`)하므로 **배경 폴링 없이는 발화 불가** — B1과 C-3은 한 항목(B 정정, C 합류).
- **덧붙여(리뷰어 보고, A 신규)**: PR은 **리뷰어 요청 없이** 열린다(repo.ts에 reviewer/requestReview 0건 — 의장 실측 ✓). 고르지 말고 읽어라: `requested_reviewers`를 넘김 성공 화면·칩 title에 한 줄(있으면 `개발자 2명에게 갔습니다 · 김OO · 이OO`, 비면 `이 레포는 리뷰어를 자동 지정하지 않습니다 — 링크를 개발자에게 보내 주세요` + `링크 복사`). 기계적 신호 계급·소유권 무손상·비용 1. 온보딩 5번째 게이트·사람 지정 UI는 기각(A).

### 3위 C-1 — 답변 끝 "만든 화면"이 미리보기를 여는 칩이 된다 (5/2)

- **빈 곳**: 지침이 이미 "제목과 화면 주소를 답변 끝에" 남기게 하지만(`common-instructions.ts:16`) 그 목록은 평문 — 답변에서 미리보기로 가는 문이 없다(`components.tsx:1109-1116`). 세 문(주소창·피커·⌘K)은 전부 미리보기 열(`ScreenPanel.tsx:164` "one declaration, three doors") — 화면 이름이 발화하는 대화 열은 문이 없던 벽.
- **A의 근거 보강(결정적)**: `ui-planner-e2e.png`에서 답변이 화면 둘을 만들었다고 말하는 동안 미리보기는 루트 `회원 관리`에 앉아 있다. 자동 따라가기·`보기` 토스트는 Claude가 직접 미리보기를 열었을 때만 발화(`ScreenPanel.tsx:646-649` `if (!opened) return;` — 의장 실측 ✓). 평범한 제작 턴을 커버하지 않는다. 기획자의 동선은 "제목→주소 번역"을 요구 — C-1이 4단계→1클릭.
- **설계**: **파싱이 아니라 대조** — 선언된 화면 목록(제목/주소)을 답변 텍스트에 대조해 맞은 것만 칩. Claude가 형식을 안 지켜도 지금과 같아질 뿐(F-A3 "준수는 확률적" 회피). 매칭 키는 **주소 문자열**(제목은 변형되기 쉽다 — B). 배관은 이미 있다: `ChatColumn`이 `screens`를 받고(`ChatColumn.tsx:51-52`), `onOpenScreen → setJumpRequest`(`PageWorkspace.tsx:557-563`).
- **조건(A)**: 칩 행은 `answer__actions`(복사·되돌리기)와 같은 줄에 두지 않는다 — 파괴적 동작과 탐색의 분리. 스트리밍 완결 시점 합류는 `answer__actions`의 기존 문법(`components.tsx:1103-1106`).

### 4위 B2 — 저장 성공 자리에서 바로 넘기기로 이어 간다 (4/1)

- **빈 곳**: `published` 상태 버튼은 `닫기` 하나(`DiffPanel.tsx:477-480`) → 닫고 → 상단 바에서 primary된 넘기기 찾고 → 두 번째 모달에서 두 번째 Claude 초안 대기(`HandoffPanel.tsx:71-89`, 최대 8초). 한 번 저장 = 성공 문장 2개·스피너 2개·Claude 초안 2회. 넘긴 요청이 열려 있을 때의 저장은 "요청에 함께 담겼다"는 사실이 칩 title에만 숨음(`delivery.ts:122`).
- **최소판**: `published`에 `이어서 개발자에게 넘기기` 버튼 + 성공 문장 분기(`넘긴 요청 N번에 함께 담았습니다`). **+ 목적지 한 줄**(B의 A 공격 답변): 두 모달 머리에 `→ colo-org/payments-web` — 되돌릴 수 없는 동작이 어디로 가는지 그 자리에서 말한다(동명 프로젝트 혼동 방지; 사이드바 title 항상 owner/repo, 이름 충돌 시 부제, RepoPicker 기본 이름 owner/repo도 함께).
- **감동판(수정)**: 저장 직후 선제 Claude 초안 금지(C: 구독 지출·초안 무효화) — **저장 메모 시드 즉시 초안 + `다시 받기` 버튼으로 Claude 대기 선택화**(handoffPrompt repo.ts:470-482 재사용). 선제 실행은 세션 idle일 때만(A).
- **B3 편입(문장)**: 변경 요청 루프의 "고쳤다" 신호 — **칩 7번째 상태는 기각**(A 반박: "리뷰 뒤 저장" ≠ "그 요청을 고침" — 기계적 신호 헌법 위반, README:67-68). 저장 문장+칩 title로 사실만. **본판은 감동판**: `changes_requested`에서의 저장이 PR에 한 줄 코멘트+재리뷰 요청(GitHub이 실제로 보고할 사실을 만든다 — 칩이 추측 없이 움직인다). `답하기`식 1회 확인 재사용(ScreenPanel.tsx:1255-1263). 별도 사이클.

### 5위 A-3+B5 — 칩을 누르면 나침반이 지도가 된다 (4/1)

- **빈 곳**: 칩은 클릭·확장 불가 `<span>` + title 한 문장(`ScreenPanel.tsx:769-778`). 6상태의 순서와 의미는 README에만 산다. `상태 확인`을 누르면 코멘트 모달이 열리고 코멘트 없으면 "아직 개발자 코멘트가 없습니다"(:1248-1250) — 질문("반영됐나?")과 답이 어긋난다(B5).
- **최소판**: 칩(옆 트리거) 팝오버 = **지금 상태 한 줄 + 다음 한 동작 한 문장 + 마지막 확인 시각·지금 확인**(B5 흡수) + 목적지 한 줄(owner/repo). 이유 문자열은 `delivery.actions.*.reason`에 이미 있다. **판정 문장은 `delivery.ts`가 소유**(`Delivery`에 `next: { line }` 필드) — 칩 팝오버와 개발자 패널 머리가 같은 필드를 읽는다(사이드바 배지의 기존 규율 :10-11 확장, A 합의안). 코멘트 모달은 코멘트가 있을 때만 열게 한다.
- **a11y 주의(B)**: `role="status"` 라이브 리전을 버튼으로 바꾸면 갱신 낭독이 끊긴다 — 칩 옆 별도 트리거 또는 aria-live 텍스트 유지.
- **짝(C)**: 강조의 이동 목격 — primary가 저장→넘기기→저장으로 옮겨갈 때 새 primary에 `settlepulse` 1회. 막대에 하나도 안 더하고 D81 유지, "왼쪽→오른쪽→반영되면 왼쪽"이 리듬으로.
- **감동판(시간 기록)은 별도**: `Delivery`가 시각을 안 들고 있다(C 비용 정정) — 저장 기록엔 있고 넘기기엔 없는 짜맞춤이 필요, 비용 3+.

토론 진행 중 README가 개정됐다(동시 편집 작업트리): 페르소나가 "기획자"에서 **모든 비개발자(기획자·디자이너·사업·운영)**로, 입력 계약이 **"입력은 뭐든 된다 — 기획서·그림·말, 기획서는 가장 빠른 길 하나일 뿐"**(README.md:17-23)로. 팩트시트는 구 계약("사용자: 기획자")으로 작성됐으므로 영향을 판정한다:
