# 화면 구성 재설계 — 클린 룸 3안 (Claude chat만 아는 사용자)

> 작성일: 2026-09-16

> 사용자 전제: **Claude Desktop의 claude chat만 써본 기획자.** 아는 UI 문법 = 대화 목록 / 스크롤 / 입력창 / artifact 패널.
> 목업: `mockups/layout/fresh-{chat,product,journey}.html` — 전부 렌더 검증 완료.

## 세 안 한 줄씩

| 안 | 모델 | 출발점 | 한 줄 |
|---|---|---|---|
| fresh-chat | GLM-5.3-Flash | 대화가 전부 | 새 화면을 하나도 만들지 않는다 — 미리보기·저장·넘기기·반영이 전부 대화 안의 카드와 타임라인 |
| fresh-product | GLM-5.3 | 제품이 주인공 | 창 전체가 사용자가 만든 화면, 대화는 부를 때만 뜨는 하단 시트 |
| fresh-journey | SWE-2 | 여정이 구조 | 여정의 단계가 창 전체를 결정하는 장면 — 전환은 스테퍼가 아니라 버튼 클릭 |

## 세 안이 우연히 합의한 것 (클린 룸이라 더 무겁다)

1. **왼쪽 대화 목록은 세 안 모두 그대로다.** Claude chat의 유일한 내비게이션을 아무도 건드리지 않았다 — 이 사용자에게 목록은 "파일 탐색기"가 아니라 "내가 하던 일들"이다.
2. **git은 버튼 라벨과 카드 문장으로만 존재한다.** 세 안 모두 저장/넘기기/반영됨 세 단어로 수렴. 브랜치·커밋·PR 문자열 0건.
3. **"넘긴 뒤 기다림"을 대화 문법으로 환원한다.** chat은 타임라인 카드, product는 화면 가장자리 메모, journey는 대화에 도착하는 사람의 메시지 — 셋 다 "개발자의 말 = 채팅에 온 답장"으로 번역했다. 이 지점이 이 사용자에게 가장 불안한 순간이라는 진단도 일치.
4. **행동은 장면당 버튼 하나.** 셋 다 "다음에 누를 것"을 복수로 제시하지 않는다.

## 세 안이 갈라지는 유일한 축 — 대화와 화면의 주종

```
chat    : 대화가 몸통, 화면은 대화에서 열리는 패널 (artifact 문법)
journey : 장면이 몸통, 대화와 화면은 장면의 부품 (역할이 장면마다 바뀜)
product : 화면이 몸통, 대화는 화면 위에 얹히는 시트 (문서앱 문법)
```

이 축은 "사용자가 이 앱을 무엇이라고 생각하는가"의 선택이다 — 채팅 도구(결과물이 부산물) / 여정(지금 어느 장면인가) / 화면 편집기(대화가 수단).

## 각 안의 최대 리스크

- **chat**: 긴 대화 = 긴 스크롤. 10번째 사이클부터 과거 저장 카드 회상이 어렵다. 상태가 카드·칩·사이클바 3곳에 있어 단일 상태 머신 필수(목업 JS가 1:1 동기 증명).
- **product**: 미리보기 위 점선 핀 오버레이는 실제 앱 DOM에 마커를 심는 일 — 임의 프레임워크에서 셀렉터 안정성이 리스크. "저장 안 하고 껐다" 공포는 문서앱 문법의 대가 — 종료 확인 필수.
- **journey**: 창이 통째로 바뀌는 게 "리셋"으로 읽힐 수 있다 — 사이드바·대화 스크롤의 장면 간 연속성이 완화책. 여정 전체 지도를 한눈에 보는 방법이 없다(의도된 절충).

## 권고

**chat을 기본 골격으로, journey의 장면 C(검토 중)를 그대로 이식.**

- chat은 학습 비용이 문자 그대로 0이다 — Claude chat과 1:1 대응. 첫 화면이 "대화가 아직 시작되지 않은 첫 메시지"라는 설계는 토큰 온보딩까지 대화 문법으로 흡수한다.
- journey의 장면 C는 세 안 중 "기다림"을 가장 잘 푼다 — 보낸 화면의 동결 스냅샷 + 코멘트가 대화 메시지로 도착 + 입력창이 답장 채널로 살아 있는 조합. 이 조합은 chat의 대화 안에 그대로 들어간다(타임라인 카드 + 동결 스냅샷 패널).
- product는 이 사용자에게 두 번째로 배울 문법이다 — "화면이 몸통"은 맞는 방향일 수 있지만, 첫 버전이 아니라 **사용자가 익숙해진 뒤의 전환 옵션**(시트를 접으면 product가 됨)으로 두는 게 순서상 맞다. chat의 패널을 전폭으로 키우면 product에 도달하므로 두 안은 연속이다.
