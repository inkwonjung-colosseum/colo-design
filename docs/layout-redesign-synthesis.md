## 1. 네 제안 한 줄씩

| 안 | 모델 | 한 줄 | 심판 평가 |
|---|---|---|---|
| A | Sonnet-5 | 주의 보드(4열 칸반) 홈 + 대화 드로어 | 칸반의 열 이동 상호작용이 없어 장식; "새 답 옴" 열에 필요한 읽음 필드가 데이터에 없음 |
| B | GLM-5.3 | 두 개의 방: 「지금」 피드 ↔ 「작업대」 | 진단·코드 근거 최정밀; 레일 폐기가 회상 경로를 끊고 NativeHost 풀-티어다운 리스크 |
| C | GLM-Flash | 미리보기가 몸통(1fr), 대화가 오른쪽 날개 | 데몬 변경 0의 정직한 안; "허가 카드 뜨면 날개 강제 펼침" 자기 규칙이 접힘의 존재 이유를 부정 |
| D | SWE-2 | 받은편지함 홈 + 미리보기 도킹 패인 | B와 동형의 안전한 변형; 사이클 액션의 스레드 헤더 이동은 프로젝트 스코프 계약 위반(기각) |

## 2. 두 심판의 합의 (채택)

1. **홈은 피드다, 칸반이 아니다** — 열은 사용자가 배정하는 게 아니라 `ThreadSummary.state`가 결정하므로 칸반의 상호작용이 없다. `badgeFor` 우선순위 정렬 피드가 같은 답을 더 적은 기계로 준다.
2. **레일은 남긴다** — ⌘K는 회상의 도구지 발견의 도구가 아니다. 비개발자의 "저번에 하던 그 대화"는 트리 스캔이 답한다. 레일 최상단에 「지금」 진입 행만 추가.
3. **사이클 칩·저장·넘기기는 프로젝트 표면에 남는다** — `pendingChanges`/`handoff`/`shelf`는 전부 프로젝트 단위(`project.ts:37-42`). 스레드 헤더로 옮기면 "이 대화만 저장됐다"는 오해를 만든다.
4. **허가 승인은 대화 안에서만** — `resolvePending(requestId)`는 전역이라 카드 인라인 승인이 기술적으로 가능하지만, 허가는 읽은 뒤 내리는 판정이다. 카드는 요청 전문 + "대화에서 보기"까지.
5. **스테퍼 부활 금지 유지** — 피드는 번호·단계 없이 "지금 어디 + 다음 한 수"만 말한다(`delivery.ts` 판정 준수).

## 3. 두 심판의 불일치 (판정 보류)

**미리보기의 위치.** Sonnet: C+D 합성(화면 있으면 몸통, 없으면 대화 전폭)을 3단계로. SWE-2: "미리보기는 화면의 유일한 문"이라 상시 유지, C의 반전은 별도 실험. → **실측 게이트로 미룬다**: 1·2단계 후 "대화를 읽는 시간 vs 무대를 보는 시간"을 재서 결정. 지금 어느 쪽도 채택하지 않는 게 양쪽 판정의 교집합이다.

## 4. 권고 구성

```
┌────────────┬──────────────────────────────────────────────────┐
│ ◐ Colo  ⟨  │  지금 — 나를 기다리는 일 3건                       │
│ ┌────────┐ │  ── 나를 기다리는 ────────────────────────── 2 ──  │
│ │✉ 지금 ③│ │  ● 장바구니 빈 상태 · 쇼핑몰                       │
│ └────────┘ │    "공용 버튼 파일을 고쳐도 될까요?"  [대화에서 보기]│
│ ▸ 쇼핑몰   │  ● 회원 관리 · 개발자 코멘트 도착         [열기]    │
│   • 대화   │  ▣ 치워둔 작업 1건 · 쇼핑몰              [꺼내기]   │
│ ▸ 관리자   │  ── 지금 작업 중 ───────────────────────── 1 ──    │
│ ＋프로젝트 │  ● 결제 실패 플로우 · 쇼핑몰          1분 42초째    │
│ ⚙ 설정     │  ── 지난 일 ─────────────────────────────── ▾      │
└────────────┴──────────────────────────────────────────────────┘
   대화를 열면 → 현행 작업 모드 그대로 (레일 | 대화 | 미리보기)
```

- 「지금」은 **일이 있을 때만** 현관 — 일도 없고 마지막 대화도 없으면(신규 사용자) 빈 대화 시작 화면으로. §7-2 참조.
- 카드 문구는 `delivery.ts` 단어 상수, 우선순위는 `badgeFor`, 경과는 데몬 시계 — 새 어휘 0.
- "모두 읽음" 없음 — 카드는 치움이 아니라 **처리됨**으로 무리를 떠난다.
- 치워둔 작업은 더 보기 메뉴에서 카드로 승격("회색은 분실의 시작" 경고의 표면 해결).

## 5. 단계적 도입 (되돌릴 수 있는 순서)

| 단계 | 내용 | 새 데이터 | 되돌리기 |
|---|---|---|---|
| 1 | 레일 「지금」 행 + 팝오버(`selector__menu` 관용구로 awaiting/running 목록) | 없음 — `ProjectSummary.threads[].state`·`badgeFor`·전역 `Pending` 재사용 | 행 삭제 |
| 2 | 피드 홈 승격 — 치워둔 작업 카드(`repo.shelf`), 프로젝트 사이클 띠(`deriveDelivery` 거울), "새 답 옴" 그룹 | 스레드별 last-seen(localStorage) 하나뿐 | 뷰 라우트 제거 |
| 3 | 미리보기 재배치 **판단 게이트** — 실측 후 C안(몸통화) 채택 여부 결정 | NativeHost bounds IPC 등, 비용 큼 | 어려움 — 그래서 마지막 |

## 6. 기각된 것과 이유

- **칸반 홈(A)**: 열 이동 상호작용이 없어 장식 + 읽음 필드 부재.
- **레일 폐기(A/B 원안)**: 발견을 검색에 맡겨 비개발자 회상 경로 단절.
- **스레드 헤더 칩(D)**: 프로젝트 스코프 계약 위반.
- **카드 인라인 허가 승인(B)**: 문맥 없는 허용 — 승인은 대화 안에서만.
- **미리보기 도킹 접힘(D)**: "화면의 유일한 문"과 충돌 + NativeHost bounds 비용.
- **대화 드로어화(A)**: "확인 요청은 언제나 옴"을 언제나 닫힌 곳에 두는 모순.

## 7. 2라운드 토론 — 확정 수정안

4심판이 최종안을 "비개발자 여정(연결→만들기→저장·넘기기→검토 루프+매일 리듬)"으로 심문(`docs/layout-verdicts/`). 골격은 유지, 아래 수정이 채택 조건.

| # | 수정 | 근거 | 단계 |
|---|---|---|---|
| 1 | **사이클 바 전폭 승격** — `.cycbar`를 미리보기 열에서 작업 모드 머리 줄로 | 칩은 프로젝트 것인데 오른쪽 귀퉁이에 있어 "이 대화의 상태"로 읽힘. 전폭 줄은 두 열 위에서 프로젝트 귀속을 물리적으로 말함. C의 조각을 몸통화와 분리해 선취 | 1 |
| 2 | **첫 실행 착지 규칙** — 일 있음→홈 / 마지막 대화 있음→복원 / 둘 다 없음→빈 대화 시작 화면(홈 아님) | 신규 사용자에게 "기다리는 일 0건" 홈은 빈 서류봉투. 첫 지시를 이끄는 자리는 빈 대화의 시작 칩 | 1 |
| 3 | **카드 스코프 계약** — 카드는 사건의 주인을 따라간다: 스레드 사건→`openThread`, 프로젝트 사건(코멘트·치워둔·저장 실패·반영됨)→프로젝트 활성화+소유 표면을 연 채로(코멘트→`devPanelOpen`) | 코멘트·치워둔은 프로젝트 사건인데 카드가 스레드 모양이면 착지가 틀리고 제목 규칙이 파열됨 | 2 |
| 4 | **`ProjectSummary` 미러 셋** — `shelf` 유무·`handoff.unhandledComments`·`ThreadSummary.turnStartedAt` + **카드 등급제**(상태 카드: 전 프로젝트·카운트만 / 사건 카드: 활성·인용 포함) | 비활성 프로젝트는 코멘트 인용·치워둔·경과 시계를 못 지음 — 아침(피드가 가장 필요한 때)에 피드가 가장 얕아지는 역전. 미러 셋=데이터, 등급제=그 데이터가 허용하는 만큼만 말하는 규칙 | 2 |
| 5 | **홈↔작업 모드 마운트 규약** — 작업 모드는 홈 아래 마운트 유지, `usePreviewCover`가 홈을 모달류로 취급 | `display:none`이 ResizeObserver로 NativeHost bounds를 0으로 미는 사고 방지 | 2 |
| 6 | **카드 문구 계약** — 데이터 없으면 인용 생략하고 "열어서 보기"; "반영됨" 카드는 "열면 제품에 내려앉습니다" 지연 고지 | 폴링이 merged를 세워만 두는 지연(`project-fleet.ts`)을 카드가 숨기면 거짓말 | 2 |
| 7 | **`cycstrip` 다중 프로젝트** — 저장 안 함인 프로젝트마다 띠 하나, 2개 초과 시 접힘 | 목업이 1개만 그린 빈칸 | 2 |
| 8 | **레일 「지금」 팝오버에 사건 내용** — awaiting/running 스레드 + 프로젝트 사건을 행으로 | 1단계가 "배지의 확대"에 그치지 않게; 작업 모드 하단 트레이 요구를 흡수 | 1 |

**기각·보류**: 작업 모드 하단 상시 트레이(대화 열 면적을 뺏어 원 진단과 충돌, 팝오버로 족함) / 미리보기 몸통화(3단계 게이트 유지 — 1번 수정이 C의 절반을 선취해 게이트 질문이 더 좁아짐) / 다건 순차 처리 전용 장치(실측 후 재검토).

**미해결 잔여**: 미러 셋의 실제 비용 — `pollOpenHandoffs`가 비활성 프로젝트의 리뷰 본문까지 가져오는지는 착수 시 확인. 못 가져오면 4번이 커지고 등급제 폴백이 전면이 됨.
