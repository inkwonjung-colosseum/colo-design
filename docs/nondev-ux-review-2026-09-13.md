# Colo Design 비개발자 사용성 종합 개선안 — 2026-09-13

**방법.** 비개발자(기획자) 사용 경험만을 겨눠 3라운드의 에이전트 토론을 돌렸다.
1차는 페르소나 6개(첫날 여정 · 대기·진행 · 실패·회복 · 언어·멘탈모델 · 조직 도입 · 외부 벤치마크)가 독립 분석해
후보 40여 개를 냈고, 2차는 엔지니어링 비판자(코드로 스팟 검증 — 20여 항목 판정)와 비개발자 대리인(채점 · 시나리오 ·
빠진 것 수집)이 정면 반박했고, 3차는 조정자가 충돌 의견을 중재하고 로드맵으로 뭉쳤다.
이전 리뷰(docs/ui-ux-review-2026-09-12.md, docs/live-review-2026-09-13.md)에서 이미 고쳐진 항목은 제외했다.
모든 file:line은 비판자가 실제 코드로 재확인한 것을 우선한다.

## 한 줄 요약

이 제품의 비개발자 리스크는 화면 예쁨이 아니라 **"내 일이 어디로 갔는지 모르는 순간들"**이다.
온보딩 "수정" 버튼이 눌러도 조용하고(A1), 기다리던 확인 카드는 새로고침 한 번에 증발하며(B1),
실패는 영어로 오고(C1·C3), 토큰은 30일 뒤 조용히 만료된다(A3). 이 네 개가 한 축이고,
나머지는 그 축을 받쳐 주는 문구·창구·보호 장치다.

## 가장 아픈 순간 Top5 (비개발자 대리인 시나리오에서)

1. **첫 출근날** — "Claude Code 설치"를 세 번 눌러도 화면이 조용하다. 유료 구독이 필요하고 그 돈이 내 카드에서
   나간다는 말은 끝까지 없다. 토큰 화면의 "Contents: Read and write · SSO 승인"은 개발자 지시서다.
   묻기 싫어 40분을 검색한다. (A1+A2+A3+E2)
2. **화요일 오후의 저장** — 저장이 회사 GitHub에 올리는 행위라는 것, 그 열쇠가 30일 전 만료됐다는 것을
   "GitHub 401: Bad credentials"로 처음 안다. 사전에 한마디가 없었다. (C6+D4+A3)
3. **기다리다 창을 닫음** — 다시 열면 확인 카드는 사라졌고 턴은 영영 멈췄다. 달리는지 죽은지 알 길이 없고
   2분과 8분이 같은 스피너다. (B1+B2+B4+B7)
4. **넘긴 뒤** — push 권한 실패에는 다음 행동이 없고, 되돌리기는 거부되는데 유일한 선택지가 '변경 버리기'다.
   실수 공포가 저장을 미루는 습관을 만든다. (C8+C5)
5. **결국 개발자 책상으로** — 영어 카드, colo-design.json 수정 요구, 도움말·문의 창구 부재.
   제품 안에 질문 길이 있었다면 가지 않아도 됐다. (C1/C3+D8+E6)

## 숨은 비용 경고

밴드 1만 하면 문구는 예뻐지지만 신뢰는 그대로다 — 창을 닫으면 확인 카드는 여전히 증발하고(B1), 실패는 여전히
영어라 "고쳐졌는데도 물으러 가는 책상"이 남는다. 특히 A3의 30일 지뢰는 밴드 1 문구로 못 막는다. 만료 순간에
터지는 문제라 U3+U2가 있어야 회복된다. 반대로 밴드 2만 하면 U1·U3가 D4·D3 같은 잡음 위에 얹혀 "기능은
늘었는데 여전히 지저분하다"는 인상을 남긴다 — 공수 S짜리를 미루는 대가로 M짜리 효과를 잃는 최악의 환율.
가장 위험한 조합은 밴드 3을 밴드 1로 위장하는 것: 서명·OAuth 없이 보안 문서만 만들면 롤아웃은 여전히 막혀 있다.

## 사실관계 교정 — 같은 항목, 다른 방법

- **A1**: "지연 자동 재확인"은 불요 — `다시 확인` 버튼이 이미 있다(Onboarding.tsx:179-186). 실질 수정은
  guidance·started 렌더뿐(S). 데스크톱 필수 경로 확인: Claude CLI는 번들되지 않으므로 실제 기획자는
  반드시 install-claude 게이트를 마주치고, macOS 설치자는 `stdio:"ignore"`라 버튼이 완전 침묵한다.

- **B1**: listPending은 `{requestId, kind, toolName}`만 돌려줘서 재전송 페이로드로 불충분(input·questions는
  pending 맵에만 있음, session.ts:490-497). 클라 append는 requestId dedupe가 없어(재접속마다 push) dedupe가
  필수, 재전송은 신규 ws에만 `send`(브로드캐스트하면 이중 카드). **S→S-M.**
- **B2**: live만 채택하면 스피너가 안 돈다 — `running` 판정은 `state` 기준이므로(useSessions:147) 둘 다
  채택해야 한다. B1과 같은 PR. **S.**
- **B4**: "주석만 지우면 됨"은 과장 — 렌더 코드 신규 작성이다. **턴 카드 소요 시간 표시 = S**, 진행 중

- **B5**: resultText는 와이어엔 있으나 foldEvent의 turn 블록에 실리지 않는다(daemon-client.ts:71-78) —
  블록 확장 필요. SDK 문자열 의존 파싱은 취약하므로 "usage limit" 부분 매칭+원문은 자세히 폴드로. 핵심은
  **한도 카드에서 다시 보내기 버튼 숨기기**. **S-M.**
- **C3**: "error-words 사전 경로로"는 원리적 불가 — 크래시 detail은 id가 아니라 메시지 문자열이라 매칭이

- **C6**: REST 경로의 401은 이미 한국어다(github.ts:88,162,189,373). 남는 갭은 git 경로뿐 —
  `PUSH_AUTH_FAILURE` 정규식에 `401|Bad credentials|expired` 없음. **C5에 흡수.**
- **D4**: 무조건 제거 금지 — 현재 브랜치명 표기는 이전 실사 리뷰의 의도적 수정이다(DiffPanel.tsx:342-343
  주석: "어디에 저장됐는지는 제품의 약속 그 자체다"). 교체 방향: `"저장했습니다 — 회사 GitHub에 올렸습니다"`
  + 브랜치명은 `title` 속성으로. **S.**
- **D7**: 방향 수정 — '개발자 변경 받기'는 악화다(340px 컬럼에서 아이콘 축소, ui-publish-e2e:231이
  "최신화"로 클릭해 깨짐). 정답은 버튼을 이미 SSOT처럼 쓰이는 **"최신 변경 받아오기"로 통일**(S+테스트 1줄).
- **B7**: 로드맵에서 빠져 있었다 — 복원. DaemonNotice가 이미 sessionId를 보유(server.ts:104-120)라
  프로토콜 변경 불요. 남은 다리는 main→renderer 채널+`resume(sessionId)` 호출(useSessions:380에 이미
  존재). **S-M, 밴드2에 추가.**
- **B3**: 질문 시점은 window-all-closed가 아니라 mainWindow "close"(preventDefault)여야 한다 —

- **C1**: 깨지는 문자열 매칭 테스트 0개 확인. 단 "다시 시도해 주세요"는 비멱등 요청의 이중 실행을 부를 수
