# 최고의 화면 — 4모델 정점(hero) 제안 종합

> 작성일: 2026-09-16
> 방법: 같은 브리프(`.local/share/hero-brief.md` — "이 앱의 정점이 되는 화면 하나")를 4개 모델이 서로 다른 출발점에서 수행 → 각자 `mockups/hero/*.html` 목업 + 제안서.
> 목업: `mockups/hero/chat.html`(glm-5.3-flash) · `product.html`(glm-5.3) · `journey.html`(swe-2) · `home.html`(sonnet-5)

---

## 0. 한 줄 결론

**넷은 경쟁 관계가 아니라 한 앱의 네 장면이다.** 「돌아왔을 때」(home) → 「일하는 중」(chat) → 「지금 어디인지」(journey) → 「결과물에 몰입」(product). 권고 조합: **home을 앱의 문으로, chat을 작업면의 기본값으로, journey의 지도를 대화 상단의 얇은 띠로, product를 미리보기의 확장 상태로.**

---

## 1. 네 제안 한 줄씩

| 안 | 모델 | 정점으로 고른 순간 | 한 줄 주장 | 핵심 장치 |
|---|---|---|---|---|
| chat | glm-5.3-flash | 개발자 검토 결과가 메시지로 도착한 직후 | 반려조차 새 화면이 아니라 답장 한 번 | 대화 안 화면 카드·상태 카드·진행 한 줄·사람 메시지 — Claude chat 문법 그대로, 새 화면 개념 0개 |
| product | glm-5.3 | 방금 나눈 말이 실제 앱 화면에 도착하는 순간 | 미리보기가 창의 97%, 대화는 접히는 층 | 문서앱 제목바(바꿈6·저장 안 됨→저장→넘기기), 고침 표시 ③④⑤⑥↔핀 1:1, 넘기면 동결 도장 |
| journey | swe-2 | 여정 전체를 통과하는 순간 | 창 전체가 여정 무대, 장면 전환은 사용자의 버튼이 일으킨다 | 상단 여정 지도(연결→만들기→저장→넘기기→반영), 장면별로 의미가 바뀌는 미리보기, 사이드바 여정 묶음 |
| home | sonnet-5 | 3시간 비우고 돌아온 순간 | 홈은 "뭐 만들까"가 아니라 "뭐가 나를 막고 있나"의 인박스 | 결정 필요 카드(질문 인용+즉답 칩) → 진행 중 → 방금 있던 일, 3단계 알림 위계(로그/뱃지/푸시) |

## 2. 무엇이 겹치는가 — 넷이 독립적으로 같은 결론에 도달한 것

1. **개발자 코멘트는 리뷰 화면이 아니라 대화에 도착하는 메시지다.** chat(메시지+인용+고치기 칩), journey(대화 카드), home(카드 안 인용+"대화에서 보기") 셋이 같은 번역. Conductor Checks류의 별도 검토면은 비개발자에게 필요 없다는 합의.
2. **"보낸 화면"은 동결 스냅샷이다.** product(탈색+도장), journey(그때 그대로 패널) 둘 다 넘긴 시점의 화면을 고정해 보여준다 — 개발자가 보는 것과 내가 보는 것을 같게.
3. **사이드바는 날짜가 아니라 상태로 묶는다.** journey(만드는 중·넘긴 것/반영됨), home(확인 필요/작업 중/저장됨/반영됨 메타), chat(저장 안 됨/반영됨 메타) — 셋 다 시간순 평탄 목록을 버림.
4. **상태는 칩 하나가 아니라 문법이다.** product의 제목바, journey의 컴포저 위 칩, chat의 "저장 안 된 변경 1개" 배너 — 전부 "문서앱에서 저장 상태를 읽던 근육"을 재사용.
5. **3단계 알림 위계.** home이 명식화(로그→뱃지→진짜 막힐 때만 푸시), journey가 동의(코멘트는 카드+메타로, 푸시 없이).

## 3. 유일한 진짜 충돌 — 대화가 주인공인가, 제품이 주인공인가

- **chat**: 대화가 창의 중심, 미리보기는 대화가 여는 오른쪽 패널. 근거: Claude chat만 아는 사용자에게 새 화면 개념 0개.
- **product**: 미리보기가 창의 97%, 대화는 접히는 오버레이. 근거: "말이 화면이 된다"는 약속의 증명은 표가 바뀌는 걸 보는 것뿐.

이전 라운드(「미리보기 몸통화」 쟁점)와 같은 축이다. 이번에도 판정은 같다: **기본값은 chat, product는 미리보기 패널의 "크게 보기" 확장 상태.** 이유 —

- chat의 정점(검토 결과 도착)은 대화 없이 성립하지 않는다. product의 정점(표가 바뀜)은 대화가 접혀 있어도 성립한다. 즉 product는 chat의 부분 상태로 표현 가능하고, 역은 불가.
- product 스스로 인정한 리스크: "긴 계획·탐색형 대화는 시트에 담기 어렵다" + "미리보기 신뢰가 단일 실패점". 기본값으로 두면 빌드 실패 시 앱 전체가 공허해진다.
- 단, product의 두 장치는 기본값에도 흡수해야 한다: **문서앱 제목바 문법**(바꿈 N·저장 안 됨 → 저장 → 넘기기)과 **고침 표시↔핀 1:1 번호**.

## 4. 권고 조합 — 한 앱의 네 장면

```
[앱을 열다]                    [대화 하나를 열다]
┌──────────────────────┐      ┌────────────────────────────────────┐
│ home: 인박스          │      │ 상단: journey 지도 띠 (얇게, 읽기전용)│
│  나를 기다리는 일 2    │ ──→  │ ┌──────────────┬──────────────────┐│
│  지금 진행 중 2       │ 클릭 │ │ chat: 대화     │ 미리보기 패널     ││
│  방금 있던 일 3       │      │ │  화면카드·상태  │  제목바: 바꿈N·   ││
│                      │      │ │  카드·사람메시지│  저장안됨[저장]   ││
└──────────────────────┘      │ │              │  [넘기기]        ││
                               │ │              │  ③④⑤⑥ 고침표시   ││
                               │ └──────────────┴──────────────────┘│
                               │ 컴포저: [저장 안 된 변경 N][지금 저장]│
                               └────────────────────────────────────┘
                                        ↕ "크게 보기" 토글
                               ┌────────────────────────────────────┐
                               │ product: 미리보기 전체화면           │
                               │  대화 = 접히는 시트 / 알약           │
                               │  넘기면 동결 도장                    │
                               └────────────────────────────────────┘
```

- **문 = home.** 앱을 열면 인박스. 카드 클릭 = 그 대화로 착지. (이전 종합의 「지금」 피드 홈과 같은 결론, 이번엔 카드 안 즉답 칩까지 구체화됨.)
- **작업면 = chat + journey 띠.** 대화가 주인공, 상단에 읽기 전용 여정 지도(4정류장: 만들기/저장/넘기기/반영 — '연결'은 대화 단위에선 노이즈). 미리보기 패널의 제목바는 product의 문서 문법.
- **몰입 = product.** 미리보기 패널의 "크게 보기"가 전체화면+오버레이 시트로 확장. 기본값 아님.
- **넘긴 후 = journey의 동결.** '보낸 화면' 스냅샷 + 개발자 코멘트는 대화에 메시지로.

## 5. 도입 순서

1. **chat의 메시지 종류** — 화면 카드·상태 카드·진행 한 줄·사람 메시지. 현재 대화 열의 확장이고 구현이 가장 가볍다.
2. **home 인박스** — 결정 필요 카드(질문 인용+즉답 칩). 즉답 칩이 "그 대화의 다음 턴으로 프롬프트를 보내는" 실제 동작이어야 한다는 조건 포함.
3. **journey 띠 + 동결 스냅샷** — 지도는 읽기 전용으로 시작. '보낸 화면' 동결은 dev 서버 스냅샷 인프라가 필요해 가장 무거운 항목.
4. **product 확장 상태** — 미리보기 "크게 보기" 토글로. 기본값 승격은 실측 후(이전 종합의 3단계 게이트와 동일).

## 6. 미해결 잔여

- **즉답 칩의 실체**: home의 "같은 화면에 넣기"가 대화를 열지 않고 답하는 것처럼 보이면 안 된다 — 실제로 그 대화의 다음 턴을 보내는 동작이어야 함.
- **반영됨 이후의 지도 리셋**: journey가 남긴 과제 — 새 변경이 시작되면 지도가 '만들기'로 돌아가는 2주차 여정 규칙이 필요.
- **알림 게이트 판정**: "진짜 막힌 대목만 푸시"의 기준을 백엔드가 정해야 한다 — 카피가 곧 정책.
- **동결 스냅샷 비용**: 스크린샷이 아니라 그 시점 빌드의 재현. 인프라가 없으면 스크린샷+시각으로 시작하고 업그레이드.
