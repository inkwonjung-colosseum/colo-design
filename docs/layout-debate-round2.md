# 토론 2라운드 — 수정안 수렴

네 심판의 1라운드 판정이 `docs/layout-verdicts/`에 있다(swe2.md, sonnet.md, glm53.md, glmflash.md). 전부 읽어라.

## 1라운드 수렴 현황
- 판정: 조건부 예 ×3, 조건부 아니오 ×1 — 골격(피드 홈+레일 존치+작업 모드 무손상)은 넷 다 인정.
- 독립적으로 같은 결함을 찔렀다:
  1. **카드 스코프 불일치** — 개발자 코멘트·치워둔 작업은 프로젝트 사건인데 카드가 스레드 모양 (SWE-2, Sonnet)
  2. **첫 실행 착지 규칙 공백** — 일도 대화도 없는 신규 사용자의 규칙이 없음 (SWE-2, GLM-5.3, GLM-Flash)
  3. **비활성 프로젝트 데이터 열화** — 코멘트 인용·치워둔·경과 시계는 활성 프로젝트 데이터라 비활성에선 못 짓는다 (GLM-Flash 표, SWE-2)
  4. **사이클 바 위치** — 칩은 프로젝트 것인데 오른쪽 열에 산다. GLM-5.3: 창 전폭 머리 줄로 승격(C의 조각을 몸통화와 분리). Sonnet: 2단계로 미리보기 바→전폭 이동을 이미 제안.
  5. **코멘트 카드의 착지** — "열기"가 대화가 아니라 개발자 코멘트 모달(`devPanelOpen`)을 열어야 함 (Sonnet, SWE-2)
  6. **다건 순차 처리** — 카드 처리 후 다음 건으로 이어지는 동작 없음 (Sonnet의 트레이 대안)

## 당신의 과제 — 수정안 수렴
1. **합의 목록** — 위 6건 중 실제로 합의가 성립하는 것과, 한 심판만 주장한 것을 구분하라.
2. **충돌 판정** — 수정안끼리 충돌하는 쌍이 있나? 특히: (a) GLM-5.3의 "사이클 바 전폭 승격" vs Sonnet의 "2단계에서 미리보기 바→전폭 이동"은 같은 수정인가 다른 단계인가. (b) GLM-Flash의 "약속 등급제(상태 카드/사건 카드)" vs "ProjectSummary 미러 셋"은 둘 다 필요한가 하나면 되나. (c) Sonnet의 "작업 모드 하단 트레이"는 피드 홈과 양립하는가 이중 진실인가.
3. **최종 수정안** — 최종안에 적용할 수정의 확정 목록. 각각: 무엇을/왜/어느 단계(1·2·3)에/비용. 순서대로.
4. **남는 반대** — 수렴하지 못한 쟁점이 있으면 명시.

간결하게, 판단만. 마크다운 반환, 파일 쓰지 마라.
