왜 이 순서인가

기준판정 근거
코드 거리 (구현 비용)E′는 Sidebar.tsx 레일 기본값 · 상단 스테퍼 제거 · Composer.tsx 칩 3→1 · PinTray 위치 — 전부 있는 것의 기본값 변경. F+E는 신규 표면 하나(지도) + 기존 화면 축(colo-design.screens) 재사용. B는 호스트 전환(<webview>)이 선행돼야 떠 있는 작성 바가 z-order 세금 없이 가능하다.
사용자 노출 빈도작업 화면(E)과 프로젝트 문(F)은 매 세션·매 방문의 표면 — 개선 효과가 사용 시간 전체에 곱해진다. D의 단계 흐름은 사이클당 한 번, 그마저 반복 루프와 충돌한다.
제품 원칙 정합README가 명시한 동작 모델 — 만들기와 고치기는 같은 턴(→ D의 선형 단계 탈락), 카드는 대화록에 산다(→ B의 도크·C의 모달 감점), 상태는 기계적 신호(→ F의 카드 칩이 같은 규칙을 재사용).
외부 의존성B만 docs/preview-proxy-agent-plan.md의 <webview> 전환 완료가 전제 — 전환 착수 시 재평가하고, 그 전에는 E 위에 부분 채택할 것도 없다.
되돌릴 수 있는가E′는 플래그 없이도 되돌리기 쉬운 표면 변경(기본값·라벨·위치). F는 새 표면 추가라 기존 홈을 지우지 않고 병행 실험 가능 — 실패 비용이 낮은 순서가 곧 구현 순서다.
