# 요소 핀 코멘트 모델 토론 — 커미티 수렴 보고서

- 날짜: 2026-09-14
- 토론 명제(사용자 제안): "UI 화면에 코멘트 류 해당 요소를 핀하고, '이 요소 이렇게 수정' 및 화면 수정 요청 등도 코멘트다."
- 방법: 상반된 성향의 위원 2명이 동일한 팩트시트(`.claude/committee-comment-model-factsheet.md`)로 병렬 판정(1라운드) → 교차 반박(2라운드) → 수렴. 양측 모두 저장소를 읽어 주장에 `파일:줄` 근거를 붙였다(읽기 전용). 잔여 이견은 의장 판정 8건으로 마감.
- 구성 비고: 에이전트 프로필 0개 → 프로바이더 디스커버리 폴백. A: claude/claude-opus-5(plan) · 제품/UX 전략가. B: omp/zai/glm-5.3(ask) · 엔지니어링/데이터모델 비평가(glm-acp-agent/glm-5.2는 API 키 부재로 교체). 원본 판정서: `.claude/commentmodel-committee-round{1,2}-{A,B}.md`.

## 1. 판정: 명제는 채택 — 단 "타입"의 완성 조건이 있다 (양측 수렴)

- **전송 계층에서 명제는 이미 코드가 된 진실이다.** 핀 N개 + 문장 = 턴 1개, 하나의 봉투, 하나의 로그(C1~C3). 양측 독립 검증, 같은 결론. 되돌릴 것 없음.
- **존재론에서는 반쪽이다.** "수정 요청은 코멘트의 한 타입"이라 말하려면 그 타입의 식별자(핀 id)와 의도(intent)가 로그까지 살아야 하는데, 둘 다 마지막 홉(`comments.record`)에서 떨어진다. 완성 비용은 스키마 필드 2개다.
- **해결 상태는 부활하지 않는다(자동 정리 유지).** 상태 대신 증거를 보여 준다 — 턴 종료 재앵커 보고가 먼저, 무조건.
- 위원회가 발견한 통합 진단: **핀은 태어날 때 안정 키(오버레이 UUID) 하나를 갖고, 세 표면(트레이 번호·배지 번호·기록 행)이 그것을 무시하고 제각기 위치 기반 정체성을 파생한다.** 모든 차단의 뿌리는 이 문장 하나다.

## 2. 질문별 합의

| 질문 | 합의 |
|---|---|
| Q1 구조화 | 자유문장 유지. 의도 칩 1비트가 구조화 상한. 스타일 조절기는 **폐기**(사유: "두 번째 더 약한 언어" + 레포 소유권 `README.md:31-34` 침해). 메모 입력은 1→3행 textarea로(그릇의 크기 문제, 구조 아님) |
| Q2 생애주기 | 상태 머신 불가, 고스트 수명 설계 유지. 진짜 구멍은 상태가 아니라 내구성 비대칭 — 대기줄에 들어간 핀 전송은 문장+이미지로 평탄화되어 돌아온다(`useSessions.ts:528-553`). "말은 남는다"의 명시적 예외로 문서화 |
| Q3 검증 | **턴 종료 경로 재확인 보고**("3개 중 2개 위치 확인, 1개 못 찾음" 한 줄)가 유일하게 자기비용을 지불하는 증분이며 선행. 계산·채널이 이미 존재(`preview-preload.ts:751-778`, `preview-view.ts:610-624`). 기록 팝오버 **flash 확장**(역사의 재지목, 앵커 체인 전제, 조용한 실패)도 함께 — 보완재다. 검증 UI의 강도는 앵커 품질을 상속한다 |
| Q4 통합 | 개발자 PR 코멘트와의 모델 통합 **기각** — 주소 공간(파일:줄 vs 화면 요소)·방향·수명이 모두 반대. 다리는 이미 올바른 크기로 두 개 존재(`reviewToTurn` 턴 문법, PR 본문 `### 수정 요청`). 이득은 어휘 통일 하나뿐 |
| Q5 정체성 | 앵커 폴백 체인 **`attrs.id → attrs.testId → path`**(sync에 선택 필드 2개)가 지금 살 만한 증분. `owners` 배제(production `null`), `source`는 **지목용만**(줄 번호는 검증 대상 편집에 밀림), 지문은 finder로 기각·**falsifier로 채택**(path로 찾은 요소의 ownText ≠ 캡처된 text → 배지 안 그림 — 조용한 오답을 조용한 무응답으로), shot은 알리바이, region 핀은 "요소"가 아닌 "위치" |

## 3. 의장 판정 (잔여 이견 8건)

**판정 1 (전/후 크롭): 지금은 기각(B안). A의 3중 조건(앵커 강화 + 강한 갈고리·falsifier 통과 + 현재 페이지가 그 screen/state)은 재개 계약으로 기록한다.**
A의 조건 ③이 스스로의 논거를 무너뜨린다 — 기획자가 그 화면에 있는 순간, 살아 있는 미리보기가 전 해상도의 '후'다. 저장된 '후' 크롭이 추가로 사는 것은 같은 눈높이 배치뿐인데, 재앵커된 배지 + flash가 이미 눈을 그 요소로 데려간다. 조건 ①②는 그림을 안전하게 만들지만 가치 있게 만들지 않는다. B의 "소비자 없는 보관"이 현장 증거가 바뀌기 전까지 유효. 단 B의 계약 문구를 본 보고서에 새긴다: **나중에 '후' 비교를 만들면 고스트 shot이 정확히 올바른 '전'이다.**

**판정 2 (고스트 번호 불일치): 차단 확정(양측 2라운드 합의). 수정 형태는 단일 정규 순서다.**
최소 수정: 트레이 번호를 sync와 같은 결합 순서(고스트 수 오프셋)에서 파생. 고스트의 트레이 회색 행 표시는 후속 폴리시. 원칙 문장(B의 합산 진단 채택): *핀의 모든 파생물은 핀 id를 타고 다니고, 번호는 단일 정규 순서에서 파생한다.*

**판정 3 (차용 텍스트): 차단(A 승격 채택).** PR 본문은 대외 문서다 — 메모 없는 핀 N개가 같은 문장 200자를 N번 복제해 개발자에게 간다(`repo.ts:3066-3071`). 수정: 스키마 `text`의 `min(1)` 완화(`index.ts:560`), 빈 메모는 빈 칸으로 기록, 표시 계층이 "(메모 없음)"을 그림, PR 본문 행은 차용 문장 대신 요소 라벨 + 표시 문자.

**판정 4 (intent 지속): 이번 사이클에 포함.** 미지속의 결과는 사용자 대면 허위 진술이다 — 기획자의 질문이 PR 본문에서 "수정 요청"으로 제출된다. 선택 필드 1개, 하위호환 선례 있음(`note`/`screen`). PR 섹션 제목을 의도 인식으로(`수정 요청 N건` / `질문 N건` / `수정 N · 질문 M` — 턴 카드 제목 규칙과 동일).

**판정 5 (상관 id): 이번 사이클에 계약 수리로 포함하되, Q3 증분의 선행 조건은 아니다(A의 분할 채택).**
`index.ts:1298`이 "chip, badge and store row all meet on it"이라 약속했는데 `comments.ts:78`이 행마다 새 UUID를 찍는다 — 문서화된 계약 위반은 수리 대상. 턴 안의 검증은 고스트가 조인이므로 오늘 가능하고, 조인 키는 턴을 건너는 검증(기록 팝오버 flash의 행 매칭, 재확인, PR 행 추적)의 선행 조건이다. 판정 3·4와 같은 스키마 터치이므로 한 커밋에.

**판정 6 (앵커 증분 범위): B안 체인 + `via` 필드 + ownText falsifier 모두 포함.** 셋 다 새 캡처 없이 기존 데이터만 쓴다. falsifier는 "배지가 엉뚱한 곳에 그려지는 것이 파산"이라는 기획자 기준선을 코드로 지키는 유일한 값싼 수다.

**판정 7 (`console.log` 2건): 위생 차단.** `usePins.ts:136-138`, `:166-167` 커밋 전 삭제.

**판정 8 (어휘 통일): 판정 3·4와 같은 묶음으로.** `핀`=가리키는 도구, `코멘트`=보낸 기록, `변경 요청`=개발자의 말. 다섯 이름(`핀`/`코멘트 기록`/`수정 요청 N건`/`개발자 코멘트`/`변경 요청`)의 정리는 PR 섹션 제목 변경과 같은 손으로, README 문서 스윕은 커밋 직전에.

## 5. 토론 요약 — 어디서 갈렸고 어떻게 닫혔나

- **1라운드부터 양측 일치**: 명제의 전송 계층 수용, 자유문장, 상태 부활 거부, 모델 통합 거부, cssPath 최약, owners 탈락, shot=알리바이.
- **A가 물러선 것**: 전/후 크롭을 무조건 제안에서 3중 조건부로 후퇴(원칙 서명의 대가); Q5 순위에서 `source` 강등을 스스로 철회(줄 번호는 검증 대상 편집에 밀린다는 자기 반증); 지문을 finder에서 falsifier로 역할 변경.
- **B가 물러선 것**: 고스트 번호 불일치 차단 승격 수용(조인 키 논거와 합쳐 단일 진단으로); 팝오버 flash 수용("살아 있는 배치의 검증과 역사의 재지목은 보완재"); textarea 수용; 지문의 모호성 가드 제안(A의 falsifier 재구성이 이를 능가해 채택).
- **사실관계로 닫힌 것**: dev코멘트 localStorage 상태는 "해결 상태"가 아니라 "행위자의 발신 마커"다(B의 재해석) — 대칭은 존재했고, 비대칭의 원인은 철학이 아니라 정체성(조인 키)의 유무였다(A가 그 답을 받아 요구 철회). "턴 내 검증은 고스트로 오늘 가능하다"(A의 정정) — B의 "조인 키 없이는 불가능"은 턴을 건너는 검증으로 한정됨.
