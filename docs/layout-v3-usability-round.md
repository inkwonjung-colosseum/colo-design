# final-v3 — 편의성 라운드 (구조 판정 + 실행 결함 수정)

> 작성일: 2026-09-17
> 방법: final-v2를 GLM-5.3(구조·여정 클릭 수)과 GLM-5.3-Flash(검토 칸 세로 예산·문법 누수·tooltip)가 독립 심사 → 브라우저 실측으로 검증 → 채택·기각 판정 후 `mockups/layout/final-v3.html`에 반영.
> 질문: "오른쪽 브라우저에 나타나는 화면 UI가 최선인가?" — **골격(뷰 둘 + 「다음은 ○○입니다」 문법)은 최선이 맞다. 그러나 그대로 만들면 네 여정에서 손이 두 번 간다.**

## 0. 한 줄 판정

- **구조는 답이 됐다.** 이번 라운드에서 새 레이아웃 제안은 없다 — 두 심사 모두 골격을 유지 판정.
- **남은 병목은 클릭 수와 세로 예산.** 꺼내기(2클릭→1)·허가 착지(탐색→점프)·문법 누수 6곳·tooltip 잔존 11곳·④ 목업의 실행 결함 2건.
- **인앱 브라우저가 들어올 자리를 미리 규칙으로 묶었다.** 줄의 3분류(상시/사건시/조건부)와 탭×모습 분리 판정.

## 2. ④ 목업의 실행 결함 — 실측으로 확정한 2건

브라우저로 final-v2 ④ 얼굴을 띄워 측정(본 검증이 GLM-5.3의 실측을 재현):

1. **미리보기 열 붕괴.** `body[data-view=work] .view-work{display:flex}`(final-v2.html:72-88)가 `.work{display:grid; minmax(380px,46%)}`(mockup.css:694-699)를 덮어써 미리보기 열이 **334px**(최소 380px 미만)로 줄고, 「다른 모습」 칩이 세로로 뭉개졌다 — 실측 "비어 있음" 41×90px(5줄). v3: 전환 CSS를 grid로, 칩 `nowrap`, URL은 경로만.
2. **핀 트레이가 전송 경로에 없음.** v2 ④는 핀을 미리보기 아래 `.pins`에만 둔다. 실제 전송은 컴포저의 PinTray(`Composer.tsx:1183-1205`, `onSend`에 pins 동봉) — 그림대로 만들면 메모·수정↔질문·전송이 모두 빠진다. v3: 트레이를 컴포저로, 검토 칸 아래는 요약 칩 1개(핀 0이면 줄째로 사라짐).

## 3. 검토 칸 세로 예산 — 인앱 브라우저 대비 규칙 (GLM-5.3-Flash)

700px 창 기준 칼럼 652px. 계산: 현재 ④의 고정 줄 136px(pbar 49+모습 38+핀 49) → stage 516. 브라우저 전환 후 방치하면 탭 34px 추가, 오류·에이전트 줄 겹침 시 **stage 422px(65%)**. web 탭에서 모습·핀·seg를 계속 그리면 **87px가 무효 면적**.

**줄의 3분류 (v3 채택 규칙):**

| 분류 | 줄 | 조건 |
|---|---|---|
| **상시** | 주소창 줄 / 탭 스트립 | 탭 ≥2에서만 렌더(1개면 주소창+제목이 식별자) |
| **사건시** | 오류 배너 / 에이전트 조작 줄 | 끝나면 줄째로 소멸 |
| **조건부** | 모습 줄+seg / 핀 스트립 | preview 탭에서만 / 핀 ≥1. 좁으면 핀은 요약 칩으로 접음 — **모습 줄은 접지 않는다**(검수 체크리스트) |

- **탭×모습 통합은 기각.** 수명이 다르다(탭=evict/discard 대상, 모습=cellSeen 검수 약속·핀 상황 태그·넘기기 캡처 목차). 한 줄에 섞으면 LRU가 검수 목록을 삼키는 사고가 "탭 닫힘"으로 보인다. web 탭에선 모습이 없어 절반이 뜯겨 나간다. 380px에 가로 스크롤 2겹. **문법만 통일**(같은 칩·accent·안 본 것 점).
- **seg(모바일/데스크톱)는 모습 줄 끝으로** — "어떻게 볼까" 문법이고 preview 탭에서만 유효. 카운트는 `2/4 봄` 숫자로.
- **에이전트 조작 표시 3종**: 탭 옆 점(0px) / "에이전트가 화면을 만지는 중 — ○○ 누름 · 8초" 한 줄(사건시) / 당한 요소에 1회 accent 링(0px). 경합은 actionability 대기로 사용자 승 — 별도 중단 버튼 불요.
- **가짜 stage__chrome(점 3개) 삭제** — 진짜 탭+주소창과 이중 크롬, 콘텐츠 +27px.
- **깎는 순서 고정**: 핀 스트립 → 탭 스트립(1개면) → 모습 카운트 문구. 스테이지 320px 바닥은 판정 책임 표면이라 마지막까지 지킨다.

## 5. 기각 6건

| 제안 | 이유 |
|---|---|
| 탭 스트립에 「다른 모습」 얹기 | 수명 결합(LRU가 검수 목록 삼킴) + web 탭 찢어진 줄 + 폭 |
| 허가를 홈 카드·알림에서 한 번에 승인 | "문맥 없는 허용" 재현 — v3는 읽는 자리로 데려간다(점프·플래시) |
| 머리 줄에 스레드 상태(확인 대기) 올리기 | 프로젝트 스코프 계약 위반(D안 기각 재현) |
| 저장→넘기기 한 버튼 병합 | 4클릭은 두 개의 판정(되돌림 없음 / 받을 것 미리 읽기) — 버튼 하나화는 선정이지 병합이 아님 |
| 사건 표지(오류·조작 줄) 상시화 | 연 60px 세금 + "멈춘 것인가" 언어 재탁탁 — 사건시만 |
| 세로가 모자라 스테이지 깎기 | 판정 책임 표면 — 깎는 순서 고정으로 방어 |

## 6. 대가 · 리스크 · 잔여

- **[꺼내기]의 잠김** — AI가 도는 중엔 잠기고 기존 문장(“AI가 고치는 중 — 끝나면 꺼낼 수 있습니다”)이 이유를 말한다.
- **점프·플래시의 과잉** — 카드가 시야에 있으면 점프하지 않고, 플래시는 1회.
- **세로 예산 규칙의 복잡도** — 줄 렌더 판정은 PreviewHost 한 곳에 모은다(단일 원천).
- **잔여**: "안 본 모습 [지금 보기]" 복귀 규칙(매트릭스를 복도 위 오버레이로, 닫으면 복도 유지)은 DiffPanel·HandoffPanel과 함께 구현 단계에서. 좁은 화면(≤880px)에서 검토 칸을 숨기는 폴백은 실제 앱의 규칙(레일 44px 접힘·대화 바닥 320px)과 정렬돼 있으나, "검토 칸이 없는 동안 상태 확인" 경로의 발견성은 별도 검토.
- **미검증**: v3는 목업 수준 — `packages/web` 실구현 착수는 별도 착수 판정(이 문서 §4 표가 착수 목록).
