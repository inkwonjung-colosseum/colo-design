## 2. 채택 상세

### G1 — 갤러리 카메라: 기계가 이미 찍는 사진을 기획자가 처음 본다 (A4+B5+C③②·③)

**금맥.** 넘기기마다 `captureHandoffShots`(`server.ts:917-949`)가 선언된 화면×상태 전부를 오프스크린 드라이버로 찍어 PR에 커밋하는데(`repo.ts:1206-1242`), `packages/web/src`의 `shots` 소비처는 0건 — 사진 찍는 도구의 UI에만 사진이 없다. 세 위원이 1라운드에서 독립적으로 같은 사실에 도달했다.

계단(한 엔진 `preview.sheet { route? }` — `captureHandoffShots` 루프를 route 필터+JPEG+base64로 일반화, 프로토콜 응답 1개):

1. **넘기기 대화상자 갤러리** — 개발자가 PR에서 볼 그 사진을 넘기기 직전에 보인다. 추가 캡처 **0**(이미 찍는 중). 비어 있음·오류 상태 누락 — 개발자 코멘트로 돌아오는 대표 재작업 사유 — 를 넘기기 전에 잡는 유일한 자리.
2. **지금 화면의 상태 한 줄** — route 1개분 캡처, 클릭하면 그 상태로 이동.
3. (백로그) 저장 기록 썸네일 — `RepoHistoryEntry` 선택 필드 1개, 커밋 성공 뒤 비동기.
4. (백로그) 전 화면 컨택트 시트.

규칙: **요청형(on demand)만** — 자동 재캡처는 턴마다 화면×상태 순회(30회 로드)를 데스크톱 main에 얹는다(A 반박, C 수용). `shots: false` 존중(판정 2). 브라우저 개발 경로는 드라이버 부재 시 조용히 비활성(`server.ts:910-915` 전례).

### G2 — 넘김 감시기: 사이클의 마지막 낱말이 기획자 폴링 위에 서 있다 (C①+A②)

**진단(전원 실측 합의).** 데몬 전체에 `setInterval`이 없다. `refreshHandoff`의 유입구는 클라이언트 `repo.handoffStatus` 하나(`server.ts:1941-1942`), 웹은 활성화 때 1회 조용히 읽을 뿐(`ScreenPanel.tsx:433-435`). 그리고 README:130이 약속한 "빌드가 깨져 있어도 요청은 열린다 — 고칠 곳은 요청 안에서 개발자가 본다"의 **검사 결과를 읽는 코드가 어디에도 없다** — `github.ts` 전면에 check-runs·statuses 부재, `HandoffStatus`는 5필드. 넘긴 작업이 막히는 가장 흔한 사유(CI)가 아무에게도 보이지 않고, 병합·코멘트도 기획자가 직접 누르기 전까지 침묵한다. 제품에서 끝이 없는 유일한 기다림(단위: 며칠).

**구현(한 PR 두 커밋).**
- `refreshHandoff` 확장: `withReviews` 옆에 `withChecks`(`repo.ts:1293-1334` 패턴) — `GET /commits/{sha}/check-runs` 하나, 같은 토큰·같은 클라이언트.
- 감시기: 열린 넘김이 있으면 5분 타이머로 확장된 `refreshHandoff` 호출(읽기 전용 모드 — 판정 1). 상태 변화는 기존 `setCycle→emit→repo.status` push 파이프 타기(`repo.ts:2103-2108`, `server.ts:637-644`). 웹 타이머는 만들지 않는다.
- UI: 상태 칩 옆 `검증 중/검증 통과/검증 실패(빌드)` 한 줄 + `Claude에게 고치게 하기` — 개발자 코멘트가 이미 가는 마커 턴 그릇(`preview-turns.ts:18-35` → `ScreenPanel.tsx:449-453` → `PageWorkspace.tsx:358-376`)에 검증 실패를 담는다. CI 로그는 못 실어도 레포의 `빌드 검사` 턴 안 재실행이 계약(README:314-317)이라 브리프 문장으로 닫힌다(B).
- 낱말: 개발자용 훅이 이미 합의한 어휘 그대로 — `검증 대기/검증 실패/검증이 회복됐어요/반영`(`scripts/pr_watch.py:7-13,199-212`).
- 알림: `DaemonNotice` 종류 추가 → 데스크톱 `notifyPlanner`(`main.ts:558-568`).

**전제(판정 1의 조건 셋 — 미이행 시 전체 부결).** `refreshHandoff`의 merged 착지는 수동 읽기가 아니다: dirty와 무관하게 `git checkout <base>`(dirty 가드가 건너뛰는 것은 `reset --hard`뿐, `repo.ts:1272-1274`)하고 `clearCheckpoints()`로 **전체** 되돌리기 스냅샷을 지운다(`repo.ts:1281-1285`, 의장 실측). 따라서: ① 타이머는 읽기만, 착지는 running 세션·미저장 변경이 없을 때만(있으면 다음 턴 시작의 최신화에 위임), ② 착지는 반드시 고지(알림+대화 한 줄 "되돌리기 기록은 정리됐습니다"), ③ 비활성 프로젝트는 읽기만.

### A1 — 첫 준비의 침묵 (5/2, 최우선)

모든 기획자·모든 새 프로젝트의 첫 30분. 기대치 문장은 피커에 하나뿐이고 누르면 사라지고(`RepoPicker.tsx:458`), 경과 시계는 채팅 턴 전용(`TurnClock.tsx`), `연결 준비`(최대 150초, `server.ts:891-900`)는 진행 레일에 칸이 없어 레일째 사라지고(`RepoProgress.tsx:25-29,65,78`), `git clone`은 `--progress` 없어 출력 0줄(`repo.ts:2172`), **설치에는 타임아웃이 아예 없다**(`repo.ts:2332-2348`; 미리보기만 120초 `repo.ts:76`) — 멈춘 설치는 얼어붙은 한 줄과 영원히 돈다. 고칠 것: 시계(`TurnClock` 재사용)·레일 1칸(`preparing`)·`--progress` 플래그(단, stderr `\r` 덧쓰기를 줄 구분자로 — B 조건)·설치 경과 안내 문장 2개. 선로 무변경.

### A3 — 되돌리기 안전망 (4/2)

되돌리기 세 갈래 중 유일하게 **비가역**인 `이 답변 이전으로 되돌리기`만 확인 없이 즉시 `rmSync`한다(`components.tsx:1117-1127` → `repo.ts:1815-1834`). 가역인 `다시 요청`은 개수까지 세며 묻는다(`components.tsx:1013-1038` — 단 마지막 답은 예외, C 정정). 수정: `ConfirmDialog` 재사용(사라질 목록 표시, `변경 버리기` 선례) + `checkpointRestore` 첫 줄에 직전 스냅샷 1회(**세션당 20개 상한 밖 별도 ref** — C 조건, 진짜 턴 스냅샷을 밀어내지 않게). README의 "역사는 지워지지 않는다"(`:142-144,295-297`)가 저장 전 작업에 대해 코드에서도 참이 된다. **G2 채택 시 체크포인트가 사라지는 경로가 둘이 되므로 선행 필수.**

### B1′ — 전·후 비교, 핀 루프 한정 (4/3)

턴 시작·종료에 보이는 뷰의 `snapshot()`(`preview-view.ts:564-582`, D89)으로 답변 카드에 전·후 짝. A의 반박 수용: `followClaude` 기본값이 켬(`settings.ts:167,392` — 의장 실측)이라 Claude가 화면을 열면 턴 종료에 미리보기가 따라 움직여 짝이 깨지는 것이 **통상 경로** — "후"는 따라가기 이전·또는 before route 복귀 후 촬영이 필요해 비용 3. 새 화면 생성(첫 사용 지배 시나리오)에서는 침묵하므로 발동 범위를 핀→고치기 루프로 명시. C의 시점 조건 반영: navigate 완료+rAF 후 촬영, 모달로 뷰가 숨었던 턴은 짝 버림.

### B3+C5 — 기획서대로인가 + 근거 문서 열기 (4/3)

`turn-marker.ts:6`이 "a 기획서 comparison"을 기계 턴의 예로 적어두고 `KINDS`에는 없는, **설계자가 비워 둔 칸**. 툴바 버튼 → `@specs/<spec>` 멘션 + "고치지 말고 표로" 마커 턴(`TurnMarkerKind` +1) — 판정은 Claude의 말이므로 "도구가 판단하지 않는다" 원칙 무충돌. C⑤의 근거 문서 서랍이 같은 표면(웹의 `spec` 소비처는 `handoff-draft.ts:32` 유일) — PDF는 `shell.openPath`로 OS 뷰어에(A 조건, 마크다운은 `Markdown.tsx` 렌더). 전제: spec 미선언 화면은 침묵이 아니라 "근거 기획서가 연결돼 있지 않아요" 안내(판정 6). 남용 방지 문구 동반(구독을 태우는 턴 — C 조건).

### B2′ — 기획서 개정판 인식 (4/3)

같은 이름 재첨부 → `이전 판: @specs/<old>. 차이를 먼저 말하고 그 차이만 반영` 프롬프트 꼬리 + `screen_list`에 `spec` 칸(`preview-tools.ts:17-21`). A의 정정 수용: `specFileName`은 접두 유무에 따라 잘린 base가 달라지는 등 세 형태의 역함수(`repo.ts:2815-2843`)라 비용 3 — 단 "도구가 접두를 붙인 형태만" 매칭하면 2로 시작 가능. **개정판 칩 필수**(판정 7): 오탐(다른 문서가 같은 일반명)을 기획자가 한 번의 클릭으로 "아니에요"로 되돌릴 수 있어야 한다.

### C2 — 대화 전문 검색 (3~4/3)

팔레트는 제목만 매칭(`Palette.tsx:142-143`)하는데 제목은 요약 도착 전 폴백 — 본문 검색 `session.search` + 스니펫. **스니펫은 마커 턴 제외**(기계 턴 본문은 CSS·파일 경로 — B 조건, 어휘 원칙). Enter 시점 스캔으로 비용 통제. 가치는 히스토리 누적에 비례 — 지금 8위, 3개월 뒤 1위 후보.

### A5 — 붙인 시안 이미지 보존 (3/2)

데몬은 이미 이미지 스펙을 받는다(`repo.ts:2804` + 주석 "keeps the source document for later sessions") — 웹이 인라인 `images`로만 보낼 뿐(`useSessions.ts:601-610`). 수정: 붙인 이미지를 `files`에도. 조건 3: 핀 크롭 분리(`kind:"shot"` 출처 표식 — 크롭은 휘발성 설계), 저장 전 긴 변 1600px JPEG 축소+해시 중복 제거(B), 이중 지불(인라인+파일 Read)은 기본 유지하되 실측 후 조정(판정 5 참조 문서화). 컴포저 드롭 대상 테두리 강조 포함.

## 3. 폐기·기각 — 토론이 걸러낸 것

- **C4 Claude 제목 명명(폐기)** — C의 전제("제목=첫 메시지 80자")가 절반만 참: 그것은 라이브 세션의 임시값이고, 실제 제목은 `info.customTitle || presentableTitle(info.summary)`(`session-manager.ts:255`, 라이브도 같은 값 우선 `:268-272`) — **Claude Code SDK가 대화록 요약을 이미 내용 기반으로 갱신**한다. 구독을 써서 공짜 일을 다시 사는 것. 잔여 결함(요약 도착 전 짧은 창)은 비용 0 표시 개선(첫 줄+…)로 충분 — 백로그.
- **B4 줄 앵커 배지 원안(폐기)** — `data-colo-src`는 선택 규약·소문자 호스트 태그 전용·dev 빌드 전용이고(`bootstrap-brief.ts:53-59`) 역방향 인덱스 부재 — 임의 줄의 코멘트를 "가장 가까운 요소"에 앵커하면 **무관한 요소를 틀린 확신으로** 가리킨다(A). 비개발자에게 확신 찬 오답은 글자보다 나쁘다. 파일 단위 옅은 표식만 백로그로 생존(B 자체 강등과 합치).
- **C3① 선택기 상시 썸네일(철회)** — 화면 선택기는 네이티브 `<datalist>`(`PreviewHost.tsx:565-580`)라 이미지를 넣을 수 없다 — 자동완성 계약 재작성(비용 4). 같은 값어치를 G1의 별도 시트가 싸게 준다. C가 원 제안자로서 직접 철회.

## 4. 의장 판정 — 잔여 이견 7건 + 순위 2건

1. **감시기의 착지 범위(A 분리 vs C 통합) — 분리 채택.** A·B가 독립적으로, 의장이 재실측해 확인: merged 착지는 dirty 무관 `checkout` + 전체 체크포인트 소거(`repo.ts:1272-1284`). 배경 타이머가 이 경로를 밟으면 "아무것도 안 눌렀는데 작업 트리가 옮겨가고 역사가 사라지는" 사건이 된다. C의 "dirty까지 안전"은 과대 서술이었고 C도 2라운드에서 조건을 받아들였다. 읽기 전용 모드 파라미터 하나로 분리, 착지는 안전 조건 하에 + 고지 필수.
2. **`shots:false`와 앱 내 갤러리(B·C 함께 끔 vs A 분리) — 기본 함께 끔 유지, 분리는 명시적 결정으로 이월.** A 스스로 인정했듯 `server.ts:922-923`은 오늘 캡처 자체를 막는다 — "분리"는 플래그 의미 변경(계약 변경)이므로 묶음에 끼우지 않고 G1 4단계(컨택트 시트)를 설계할 때 별도 결정 사항으로 기록한다.
3. **캡처 갱신(A 요청형 vs C 자동) — 요청형 확정.** A+B 수렴, C 철회. 턴 종료는 캐시 "낡음 표시"만.
4. **B4 원안(A 폐기 vs B 유지) — 폐기.** B도 스스로 백로그로 강등했고 A의 코드 계약 반박이 결정적. 파일 단위 표식만 백로그.
5. **C4(A·B 폐기 vs C 유지) — 폐기.** B가 먼저, A가 더 정밀하게 반박; C는 "측정 후 보류"로 사실상 수용. 폐기 확정.
6. **spec 미선언 시 안내 — 채택(안내).** A·B 모두 지지. 기능의 조용한 부재는 "왜 여기 없지?"를 낳는다.
7. **B2 개정판 칩(A 필수 vs B 선택) — 필수 채택.** 판정이 프롬프트 안에서만 일어나면 오탐을 기획자가 되돌릴 길이 없다 — 이 도구의 안전망 원칙과 일치.
8. **순위: 갤러리(G1)를 2위, 감시기(G2)를 3위로.** Borda 동률(9-9). 감시기의 영향(5)이 크지만 착지 안전이라는 구현 전제와 원칙 판정을 동반하는 반면, 갤러리 1단계는 추가 캡처 0·위험 0으로 즉시 출하된다 — 리스크 없는 감탄이 먼저, 판정이 필요한 감시기가 그 다음. 단 감시기의 1단계(checks 필드+트리거 표시)는 타이머 없이 성립하므로 같은 주기에 착수 가능.
9. **순위: A3을 '4위로 기록하되 실행은 G2보다 먼저'.** A의 논지 채택 — G2가 배경 `clearCheckpoints` 경로를 만드는 이상 안전망이 먼저 서야 한다.
