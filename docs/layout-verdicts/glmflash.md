보여 주듯 **다른 프로젝트의 진행 턴을 작업 모드 밖에서 읽을 수 있다**(작업 모드는 한 프로젝트의 조종실이다). 방해는 없음. 굳이 꼽으면 \"지금\" 행 ↔ 작업 모드 왕복 시 배지·활성 표시의 상태 동기가 목업에선 확인 불가 — 구현 시 사소한 검증점.\n\n### 단계 3 — 저장·넘기기: **스코프 판정은 옳고, '가르침'은 홈 띠가 맡는다**\n액션을 프로젝트 표면에 두는 판정(`project.ts:37-42`의 스코프 계약)은 정확하고, D 기각도 정확하다. 질문에 답하면 — **가르치는 장치는 미리보기 바가 아니라 홈의 띠**다: \"다음은 저장입니다 — 쇼핑몰 프론트\"의 프로젝트 접미사가 누적의 주어를 말하고, 진짜 누적의 순간은 저장 검토의 파일 목록(DiffPanel)이 증명한다. 두 가지 미완성: (a) 띠가 단일 프로젝트 형태라 두 프로젝트 이상 변경 중이면 행 늘어남이 미정의, (b) 비활성 프로젝트의 띠는 문장 없이 칩+숫자로 열화한다(위 표). 그리고 최종안 스스로 D에게 했던 물음 — \"그 표면은 어디의 것인가\" — 를 미리보기 바 위 액션에선 재묻지 않았다. 칩 title과 `next.line`이 프로젝트 어투를 쓰는 것(`delivery.ts` 단어 규율)이 유일한 완화 장치다.\n\n### 단계 4 — 검토 루프: **뼈대는 자연스럽다. 그러나 목업의 가장 좋은 카드가 지을 수 없다**\n루프 자체는 방 두 개로 깔끔히 읽힌다: 아침에 변경 요청 카드 → [열기](활성화) → 개발자 패널 읽기 게이트 → \"모두 Claude에게 (N)\"(`ScreenPanel.tsx:1557-1576`) → 고침 → \"다음은 저장입니다\" → 넘기기 → 다시 대기. 자연스럽다. 방해는 위 표의 세 번째 행: 목업의 백미 카드 — \"준호 님이 코멘트를 남겼어요 — '제목 여백만 조금 줄여요'\"(`final.html:148-156`) — 는 **비활성 프로젝트에서 인용문이 없다**. 코멘트 본문은 활성 레포의 `comments.json` 읽기+처리 표식에서만 나온다. 비활성 프로젝트에겐 \"변경 요청 — 열어서 보세요\"까지만 자격이 있다.\n\n### 매일의 리듬: **개념은 최적 적합, 그런데 정확히 아침에 눈이 멀다**\n아침=홈에서 밤새 돌던 것 확인, 지시=작업 모드, 퇴근=방치(데몬이 붙듦) — 이 리듬에 두 방 구조보다 나은 뼈대는 없다. 아이러니는 이것: **밤사이 일어난 일은 정의상 활성 프로젝트가 아닌 곳에서 생긴다.** 새 답(last-seen)과 확인 대기(전역 Pending)만이 밤의 소식을 온전히 전하고, 코멘트·치워둔 작업·경과 시계는 아침의 홈에서 열화된다. 피드가 가장 필요한 순간에 피드가 가장 얕아지는 구조다.\n\n## 3. 가장 약한 고리\n\n**홈 피드의 약속과 데이터 바닥의 불일치.** 도입표가 \"새 데이터: 스레드별 last-seen 하나뿐\"이라 쓴 것(`synthesis §5`)이 이 고리의 자백이다 — 목업 카드 7종 중 코멘트·치워둔·시계 3종은 그 한 조각으로 못 짓는다. 신뢰는 약속대로 채워질 때만 생긴다: 기획자가 아침 홈에서 \"코멘트 왔네\"를 못 읽고 트리를 열어 확인하는 순간, 홈은 \"요약이 빠진 두 번째 트리\"로 전락하고, 리설계의 출발 진단(\"13px 배지\")이 뒷문으로 돌아온다.\n\n왜 다른 안이 이걸 더 잘 푸나 — 정직한 답은: **푸는 안은 없고, 회피하는 안은 하나 있다.** A가 기각된 이유가 정확히 이 바닥(읽음 필드 부재)이었고, B·D도 같은 바닥 위에 선다. 유일하게 C(미리보기 몸통화)는 피드를 아예 약속하지 않음으로써 — 상태 깊이(`badgeFor`)만 말하는 레일 감시자로 — 무너질 바닥이 없다. 즉 C는 문제를 푼 게 아니라 문제를 걷어찼고, 최종안은 그 문제를 정면으로 받아 안 주었다. 받은 이상 바닥을 얹든 약속을 낮추든 둘 중 하나는 해야 한다.\n\n## 4. 놓친 대안\n\n레이아웃 반쪽엔 없다 — 네 제안이 \"현관+작업대\"로 수렴한 것 자체가 답이고, 드로어·칸반·스레드 칩은 이미 합의대로 기각이 옳다. **놓친 것은 구조가 아니라 약속의 등급제다:**\n\n> **상태 카드(전 프로젝트)** — 확인 대기·변경 요청·작업 중·치워둔 여부·새 답. 오늘의 데이터로 즉시 성립(`badgeFor`+last-seen+전역 Pending). 인용문 없이 \"[열어서 보기]\"만.\n> **사건 카드(활성 + 알림으로 온 것)** — 인용문·경과 시계·shelf 행. 데이터가 있는 곳에만 풀 내용.\n\n같은 `.ibx-card` 관용구에 등급만 두는 것이므로 최종안의 반려가 아니라 미완성 절반의 완성이고, 단계 1·2를 건드리지 않은 채 신뢰를 지킨다. 이 등급제 없이 목업을 그대로 구현하면 3종 카드가 조용히 빠지거나 거짓말을 하게 된다.\n\n## 5. 한 가지 수정\n\n**`ProjectSummary`에 읽기 전용 미러 셋을 얹는다**: `shelf`(치워둔 대화 id 하나) + `handoff.unhandledComments`(미처리 코멘트 수) + `ThreadSummary.turnStartedAt`. 전부 데몬이 프로젝트 스캔 때 이미 읽는
