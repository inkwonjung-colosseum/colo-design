## 새로 막힌 순간 · 결함

- **N1 (데몬)** 락파일 없는 레포 — `pnpm run dev`(pnpm 11)가 스스로 설치해 `pnpm-lock.yaml` ·
  `node_modules/` 를 만들고, 감독자의 `commitPending` 이 그것을 「작업 이어 보관」 으로 커밋 ·
  푸시한다. 아무것도 만들지 않았는데 제출이 열리고(「제출할 화면 0개 · 화면 밖 변경 1건」),
  작업 기록 첫 줄이 사람의 말이 아니라 기계의 제목이며, `이번 작업` 은 「아직 바뀐 화면이 없어요」
  라 서로 어긋난다. 픽스처에 `.gitignore` 가 없는 탓도 있지만 락파일 생성은 README 의 계약
  (「없는 락파일을 만드는 변경을 사용자의 커밋에 몰래 올리지 않는다」)을 어긴다.
- **N2 (데몬)** 떠난 프로젝트가 `phase: "pulling"` 에 붙박힌다 — `repo-bringup.ts:111` 의 울타리
  `if (!this.core.active && !firstPrep) return` 가 몇 줄 위의 `setPhase("pulling")` 를 되돌리지
  않는다. 서버는 살아 있는데 다른 프로젝트 줄은 「준비 중」, 홈은 「지금 진행 중 · 처음 켜는 준비」
  를 몇 분이고 말한다. 고칠 자리: 울타리에서 돌아가기 전에 서버가 살아 있으면 `ready`, 아니면
  들어오기 전의 단계로 되돌린다.
- **N3 (웹)** AI 답 실패 카드가 다시 읽으면 사라진다 — 보조 실행에서 실패 직후에는 카드와
  `다시 시도` 가 서지만, 새로 고침 뒤에는 날 오류 한 줄만 남고 사이드바도 「아직 만든 화면이
  없어요」 로 돌아간다. 가짜 claude(말이 닿기 전에 죽음)에서는 반대로 사이드바가 「AI가 답을 못
  했어요 — 다시 시도할 수 있어요」 라 약속하는데 대화에는 입력창 아래 빨간 한 줄뿐, `다시 시도`
  단추가 없다.
- **N4 (웹)** 제출이 다시 도는 동안 `이번 작업` 이 「아직 제출하지 않았어요. 다 만들었으면 위의
  제출을 눌러요.」 와 「다시 제출하는 중」 을 한 칸에 함께 말한다.
- **N5 (웹 · 데몬)** 첫 보내기가 실패한 대화가 「새 화면」 이라는 빈 대화로 목록에 쌓인다(한 번
  실패할 때마다 하나).
- **N6 (데몬)** 제출 막힘이 늦다 — 픽스처에 없는 요청(`GET /pulls`)은 `other` 로 분류돼 예산
  다섯 번을 백오프로 다 쓰기까지 **약 12분** `다시 제출하는 중…` 이 이어진다. 그 뒤의 흔적(여정 ·
  문제 문장)은 U13 대로 섰다. 개발자 몫의 문제를 12분 동안 「잠깐의 문제」 로 말하는 셈이다.
- **N7 (웹)** 설정의 업데이트 줄 — 업데이트를 마친 뒤에도 옆의 「새 버전 1개 · 방금 확인」 이 남는다.
- **N8 (웹)** 실제 CLI 의 모델 칩이 「Claude · Default (recommend…」 — 영어 모델 이름이 잘려 선다.
