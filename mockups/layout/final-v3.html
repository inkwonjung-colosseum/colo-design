final-v3 — 같은 골격, 덜 걷는 손

final-v2의 골격(뷰 둘 + 「다음은 ○○입니다」 문법)은 그대로 두고, GLM-5.3(구조·클릭 수)과 GLM-5.3-Flash(세로 예산·문법 누수·tooltip)의 심사와 브라우저 실측으로 다듬은 편의성 라운드입니다. 결론: 구조는 답이 됐다 — 이제 여정의 클릭 수와 검토 칸의 세로 예산이 남은 병목. 아래 목업이 v3이고, 나머지는 이번 라운드의 근거 기록입니다.

한 줄 판정

final-v2는 구조로는 최선이 맞다. 그러나 그대로 만들면 네 곳에서 손이 두 번 간다 — 꺼내기·허가 착지·코멘트 읽기·안 본 모습 복귀. v3는 그 네 걸음을 하나로 줄이고, 인앱 브라우저가 들어올 검토 칸의 세로 예산을 미리 규칙으로 묶어 둔다.

여정 — 클릭 수로 본 v3의 수확

①
허가 승인
v2: 착지 후 카드를 스크롤로 찾기(위치 무보장). v3: 착지하면 점프+플래시 — 탐색 비용 0. 연결면의 [설치 시작]도 전문을 읽는 표준 카드로.
②
치워둔 꺼내기
v2: 작업 모드에서 더 보기 ▾ → 2클릭(primary=null의 빈 사각지대). v3: 머리 줄·홈 띠의 [꺼내기] 1클릭 — "다음 한 수" 문법의 마지막 적용.
③
저장·넘기기
v2와 같은 4클릭 — 두 검토는 각자 다른 판정이라 합치지 않는다. 달라진 것: 홈 띠의 문장이 [저장하기] 버튼으로 곧장 응답.
④
코멘트→이어서
v2: [코멘트 열기] — 명령어. v3: [읽고 답하기]·[이어서 고치기] — 버튼이 결과를 말한다. 펼쳐 읽기 게이트에는 이유 한 줄이 붙는다(문구 규칙).

심사 판정 — 두 모델 + 실측

심사판정핵심 기여
GLM-5.3골격 유지 여정 4개 클릭 수 실측: 꺼내기 2클릭(primary=null 사각지대)·허가 착지 후 탐색 비용·코멘트 3+N클릭. ④ 목업의 실행 결함 2건 발견 — display:flex 덮어쓰기로 380px 최소폭 붕괴(칩 5줄로 뭉개짐, 실측 41×90px), 핀 트레이가 전송 경로(컴포저)에 없음.
GLM-5.3-Flash조건부 유지 검토 칸 세로 예산 계산(700px 창 → stage 516→422px)과 줄의 3분류 규칙 — 상시 2줄·사건시 2줄·조건부 3줄. 탭×모습 통합 기각(수명이 다르다: 탭은 evict 대상, 모습은 검수 약속). 문법 누수 6곳·tooltip 잔존 11곳 제시.
본 검증실측 재현 GLM-5.3의 실측을 브라우저로 재현 — 미리보기 열 334px·“비어 있음” 칩 41×90px(5줄)·.view-work display:flex 확인. 채택·기각 판정에 그대로 반영.

v3 수정안 — 채택된 것

#수정출처새 데이터 / 비용
1④ 레이아웃 결함 복구 — work 전환 CSS를 grid로 되돌려 380px 최소폭 복원, 「다른 모습」 칩 white-space:nowrap, URL은 경로만(상태 인자는 칩이 말함)GLM-5.3실측없음 — 목업·CSS 수정
2핀 트레이를 컴포저로 — 전송 경로(메모·수정↔질문·onSend)가 사는 곳으로 복귀. 검토 칸 아래는 요약 칩 1개(핀 0이면 줄째로 사라짐)GLM-5.3없음 — 실제 컴포넌트 구조 그대로
3치워둔 상태의 한 수 = [꺼내기] — primary:null인 shelf 행에 한 버튼(머리 줄 + 홈 띠). 문장(delivery.ts “더 보기 메뉴에서 꺼내 주세요”)이 이미 꺼내기를 가리켰다GLM-5.3action id 하나 — 상태·데이터 0
4허가 착지 점프·플래시 — 홈 카드·OS 알림로 들어오면 허가 카드로 scrollIntoView+1회 플래시. live-savecard·live-handoffcard에는 있고 허가 카드에만 없던 앵커GLM-5.3없음 — 기존 관성 복용
5연결면 [실행 허가] → 표준 허가 카드 — 한 번 누르는 맹목 승인을 “전문 읽고 세 선택지”로. [설치 시작]이 카드를 연다GLM-5.3없음 — 기존 Pending 카드 재사용
6검토 칸 세로 예산 규칙 — 상시(주소창·탭 ≥2) / 사건시(오류 배너·에이전트 조작 줄 — 끝나면 줄째로 소멸) / 조건부(모습 줄=preview 탭만·핀 ≥1). web 탭에서 모습·핀·seg를 계속 그리면 87px 무효 면적 — plan 규칙 5를 줄 렌더 자체로 승격Flash설계 규칙 — 데이터 없음
7탭×모습 분리, 문법 통일 — 탭은 evict 대상, 모습은 검수 약속(cellSeen·핀 태그·넘기기 캡처 목차). 수명 결합 시 LRU가 검수 목록을 삼킨다. seg는 모습 줄 끝으로, 카운트는 2/4 봄 숫자로Flash없음
8에이전트 조작 표시 3종 — 탭 옆 점(0px)·“에이전트가 화면을 만지는 중 — ○○ 누름 · 8초” 한 줄(사건시)·당한 요소에 1회 accent 링(0px). 경합은 actionability 대기로 사용자 승Flashplan §4 agent-driving 이벤트
9문법 누수 6곳 — 홈 띠 “다음은 저장입니다”에 [저장하기] 동봉 / 대화에서 보기→가서 답하기 / 코멘트 열기→읽고 답하기 / 열어서 보기→이어서 고치기(본문 반복 제거) / 실행 허가→설치 시작 / 꺼내기→이어서 작업하기Flash문자열만
10준비 카드 동사+경과초 — v2가 처방만 적어둔 것을 카드에: “내려받는 중 · 1분 12초”. 컴포저 힌트 줄도 상태 분기(대기 중·N초 / 대기 줄 N건)FlashGLM-5.3없음 — 데몬 시계 재사용
11tooltip 걷어내기(11곳) — 접기·설정·복사·다시 만들기·그림 첨부·확인 방식은 텍스트 병기, [↑ 보내기]는 title 삭제(힌트 줄이 이미 말함). 회귀 금지: 신설 탭·주소창·조작 줄에 title을 새로 붙이지 않는다Flash문자열만

기각된 것 — 이번 라운드에서

제안이유
탭 스트립에 「다른 모습」 칩을 얹기수명이 다르다(탭=evict 대상, 모습=검수 약속) + web 탭에서 절반이 뜯겨 나가는 찢어진 줄 + 380px에 가로 스크롤 2겹. 문법만 통일(같은 칩·accent·점)하고 줄은 둔다.
허가 승인을 홈 카드·알림에서 한 번에클릭 수를 1로 줄이는 유혹이지만 “문맥 없는 허용” — 승인은 전문을 읽은 자리에서. v3는 읽는 자리로 데려가는 데(점프·플래시)에 쓴다.
작업 모드 머리 줄에 스레드 상태(확인 대기 등) 올리기프로젝트 스코프 계약 위반(D안 기각 재현). 대기 발견은 레일 팝오버·사이드바 meta·점프 노트가 담당.
저장→넘기기를 한 버튼으로 병합4클릭은 비용이 아니라 두 개의 판정(되돌림 없음의 저장 검토 / 받을 것을 미리 읽는 넘기기). 버튼 하나화는 선정이지 병합이 아니다.
사건 표지(오류 배너·조작 줄)의 상시화좁은 칼럼에 연 60px 세금이고 “멈춘 것인가”의 언어를 다시 흐린다 — 사건시만.
세로가 모자라 스테이지를 깎기깎는 순서 고정: 핀 스트립 → 탭 스트립(1개면) → 모습 카운트 문구. 스테이지는 이 앱의 판정 책임 표면(320px 바닥 유지).

대가 · 리스크

  • [꺼내기] 버튼의 판정 위험 — 치워둔 상태에서 AI가 도는 중엔 버튼이 잠긴다. 잠긴 이유는 기존 문장(“AI가 고치는 중 — 끝나면 꺼낼 수 있습니다”)을 그대로 쓴다. GLM-5.3 자기 지적
  • 점프·플래시의 과잉 — 카드가 이미 시야에 있으면 점프하지 않는다(스크롤 위치 판정). 플래시는 1회. GLM-5.3 자기 지적
  • 세로 예산 규칙의 복잡도 — 줄 5종×조건 3분류는 구현 시 각 렌더 조건이 테스트 대상이 된다. 규칙은 PreviewHost 한 곳에 모은다(줄 렌더 판정의 단일 원천). Flash
  • 미해결 잔여 — “안 본 모습 [지금 보기]” 복귀 규칙(매트릭스를 복도 위 오버레이로, 닫으면 복도 유지)은 목업 밖 복도 화면이 그려져야 시연 가능 — 구현 단계에서 DiffPanel·HandoffPanel과 함께. GLM-5.3
